# Embed OpenSCAP natively (A2) with full scope (C3)

#### 1) Runtime and packaging
- **Dependency**: Ensure `openscap-scanner` (`oscap`) and `scap-security-guide` packages are present on runner hosts (document per OS). Preflight check endpoint to verify availability.
- **Runner**: Use existing Ansible task runner/SSH pathways to execute `oscap` remotely; collect ARF files as Forge task artifacts.

#### 2) Data model and migrations (SQL + BoltDB)
- Add tables/entities:
  - `scap_contents` (id, project_id, name, source, ds_xml path/blob, uploaded_by, created)
  - `scap_profiles` (id, content_id, profile_id, title, severity, description)
  - `compliance_policies` (id, project_id, name, content_id, profile_id, schedule_id nullable, attrs JSON)
  - `policy_assignments` (id, policy_id, target_type: inventory|host|group, target_id)
  - `compliance_scans` (id, project_id, policy_id, initiated_by, started/ended, status)
  - `compliance_reports` (id, scan_id, host, result overall, arf_path, summary JSON)
  - Optional `compliance_rule_results` (report_id, rule_id, severity, result, ident, description) for deep drilldown.
- Index by `project_id`, `policy_id`, and time.

#### 3) Backend services (Go)
- `services/compliance/content.go`: Upload/validate DS files; run `oscap info` to enumerate profiles; persist `scap_contents` + `scap_profiles`.
- `services/compliance/policy.go`: CRUD policies and assignments; resolve targets to host lists.
- `services/compliance/scanner.go`:
  - Build `oscap xccdf eval` command line with selected profile and tailoring if present, e.g.:
    - `oscap xccdf eval --profile PROFILE --results-arf /tmp/arf.xml --report /tmp/report.html /path/to/ds.xml`
  - Execute per-host using existing runner (Ansible shell module or SSH) and fetch `/tmp/arf.xml` back as artifact via the Task File system.
  - Create `compliance_scans` row; one `compliance_reports` per host; parse ARF for summary (pass/fail, score) and rules if enabled.
- `services/compliance/parser.go`: ARF XML parser (Go `encoding/xml`) → summary + rule results.
- Scheduling: integrate with existing `ScheduleManager` to trigger scans on cron for each policy.

#### 4) API (REST)
- Prefix: `/api/project/{project_id}/compliance`
  - Contents: `POST /contents` (upload DS), `GET /contents`, `GET /contents/{id}`, `DELETE /contents/{id}`, `GET /contents/{id}/profiles`.
  - Policies: `POST /policies`, `GET /policies`, `GET /policies/{id}`, `PUT /policies/{id}`, `DELETE /policies/{id}`.
  - Assignments: `PUT /policies/{id}/assignments` (array), `GET /policies/{id}/assignments`.
  - Scans: `POST /policies/{id}/scan` (ad-hoc), `GET /scans`, `GET /scans/{id}`.
  - Reports: `GET /reports?policy_id=&host=&status=`, `GET /reports/{id}`, `GET /reports/{id}/arf` (download artifact), optional `GET /reports/{id}/rules`.
  - Health: `GET /preflight` to validate `oscap` availability on runners.

#### 5) UI (Vue)
- New section under `Compliance`:
  - `ComplianceContents.vue`: upload DS XML, list profiles (from backend), view metadata.
  - `CompliancePolicies.vue`: create/edit policies (select content + profile), assign inventories/hosts, set schedule, run now.
  - `ComplianceReports.vue`: scans list, filter by policy/host/status/date, drill into a report; download ARF; optional rule-level table with severities.
- Integrate with existing `TaskComplianceTable` and dashboard tiles (counts, last scan, compliance trend).

#### 6) Execution flow
- Admin uploads SCAP DataStream → profiles discovered → policy created selecting content/profile → assignments target hosts → schedule created (or run now) → runner executes `oscap` on each host → ARF collected as task artifact → ARF parsed → report saved → UI shows pass/fail and details.

#### 7) Security & limits
- Validate XML uploads (size/type) and store on disk under project-scoped path; checksum DS files.
- Sanitize `oscap` invocation; timeouts per host; concurrency caps via existing TaskPool.
- RBAC: project-scoped permissions for contents, policies, and reports.

#### 8) Docs & ops
- Install guide for `oscap` per distro; sample content from `scap-security-guide`.
- Preflight diagnostics page; troubleshooting (common `oscap` errors, missing content, permissions).

#### 9) References
- Conceptual parity and UX inspiration: Foreman OpenSCAP plugin [foreman_openscap](https://github.com/theforeman/foreman_openscap).
