# 프로젝트 설정

프로젝트 전체에 대한 설정입니다. 프로젝트 이름, 동시에 실행할 수 있는 작업 수, 알림 전송 여부를
설정합니다. 양식 아래의 위험 구역에는 프로젝트 전체에 영향을 주는 작업, 즉 백업, 캐시, 삭제가
있습니다. 양식의 변경 사항은 **저장** 후에 적용됩니다.

## 프로젝트 이름 {#newProject-name}

사이드바 상단의 프로젝트 메뉴에 표시되는 프로젝트 이름입니다. 이 필드는 필수입니다.

## 최대 병렬 작업 수 {#newProject-maxParallelTasks}

이 프로젝트의 작업을 동시에 몇 개까지 실행할 수 있는지 지정합니다. 한도를 넘어 시작된 작업은 실행
중인 작업 중 하나가 끝날 때까지 대기열에서 기다립니다.

프로젝트 자체의 한도를 두지 않으려면 이 필드를 비워 두거나 `0`으로 설정하세요. 어느 경우든
관리자가 설정한 서버 전체의 한도가 적용됩니다.

## 텔레그램 채팅 ID {#newProject-tg}

선택 사항입니다. 이 프로젝트의 알림을 받을 Telegram 채팅입니다. 이 필드가 비어 있으면 알림은
서버 전체에 설정된 채팅으로 전송됩니다.

이 필드는 관리자가 서버에서 Telegram 알림을 켜고, 이 프로젝트에 알림이 허용된 경우에만 효과가
있습니다.

## 이 프로젝트에 대한 알림 허용 {#newProject-alert}

이 프로젝트의 작업에 대해 알림을 켭니다. 알림이 전송되는 곳은 관리자가 서버 전체에 대해 설정합니다.
이메일, Telegram, Slack, Rocket.Chat, Microsoft Teams, DingTalk 또는 Gotify입니다.

- 작업이 실패하면 해당 작업을 볼 수 있고 자신의 계정에서 알림을 켠 프로젝트 멤버에게 이메일이
  전송됩니다.
- 작업이 성공하거나, 실패하거나, 확인을 기다릴 때 메신저로 메시지가 전송됩니다.

작업 템플릿에서 성공한 작업이나 실패한 작업이 알림을 보내지 않도록 설정할 수 있습니다.

## Test Alerts {#settings-testAlerts}

서버에서 켜진 모든 채널을 통해 테스트 알림을 보내, 이 프로젝트의 알림이 도착하는지 확인할 수 있게
합니다.

이 버튼은 **이 프로젝트에 대한 알림 허용**이 체크되고 저장된 경우에만 작동합니다. 먼저 체크하고
**저장**을 누르세요.

## 프로젝트 백업 {#settings-exportProject}

프로젝트 구성이 담긴 JSON 파일을 다운로드합니다. 작업 템플릿, 인벤토리, 리포지토리, 변수 그룹, 키,
일정, 통합 및 프로젝트에 설정된 기타 항목이 포함됩니다. 이 파일은 사이드바 상단의 프로젝트 메뉴에
있는 **프로젝트 복원**으로 다시 프로젝트로 만들 수 있습니다.

이 파일에는 키의 비밀 값과 변수 그룹의 **Secrets** 탭에 있는 비밀 값이 들어 있지 않습니다. 이 값들은
복원 후 다시 입력해야 합니다. 그 밖의 모든 것은 그대로 복사되며, 다른 필드에 직접 입력한 비밀번호도
마찬가지입니다. 비밀번호가 들어 있는 리포지토리 주소, 정적 인벤토리의 텍스트, 일반 변수와 환경
변수의 값이 그렇습니다. 파일을 공유하기 전에 이런 값이 있는지 확인하세요. 작업 기록은 백업에
포함되지 않습니다.

## 캐시 지우기 {#settings-clearCache}

Semaphore가 이 프로젝트를 위해 서버에 보관하는 파일(예: 리포지토리 사본)을 삭제합니다. 이 파일들은
다음 작업이 시작될 때 다시 다운로드됩니다.

작업이 오래되었거나 손상된 리포지토리 사본 때문에 실패할 때 사용하세요. 이 작업은 되돌릴 수 없으며,
프로젝트 설정에는 영향을 주지 않습니다.

## 프로젝트 삭제 {#settings-deleteProject}

프로젝트를 그 안의 모든 항목(작업 템플릿, 작업 기록, 인벤토리, 리포지토리, 변수 그룹, 키, 일정)과
함께 삭제합니다. Semaphore는 먼저 확인을 요청합니다.

삭제된 프로젝트는 되돌릴 수 없습니다. 다시 필요할 수 있는 프로젝트를 삭제하기 전에 백업을
다운로드하세요.
