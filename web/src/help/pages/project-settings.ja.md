# プロジェクト設定

プロジェクト全体の設定です。プロジェクトの名前、同時に実行できるタスクの数、アラートを送信するかどうかを設定します。フォームの下にある危険ゾーンには、プロジェクト全体に及ぶ操作、つまりバックアップ、キャッシュ、削除がまとめられています。フォームの変更は **保存** の後に反映されます。

## プロジェクト名 {#newProject-name}

サイドバー上部のプロジェクトメニューに表示されるプロジェクトの名前です。このフィールドは必須です。

## 最大並列タスク数 {#newProject-maxParallelTasks}

このプロジェクトのタスクを同時にいくつ実行できるかを指定します。上限を超えて開始されたタスクは、実行中のタスクのいずれかが終了するまでキューで待機します。

プロジェクト独自の上限を設けない場合は、このフィールドを空のままにするか `0` を設定します。いずれの場合も、管理者が設定したサーバー全体の上限が適用されます。

## TelegramチャットID {#newProject-tg}

任意です。このプロジェクトのアラートを受信する Telegram チャットです。このフィールドが空の場合、アラートはサーバー全体に設定されたチャットに送信されます。

このフィールドは、管理者がサーバーで Telegram アラートを有効にしていて、かつこのプロジェクトでアラートが許可されている場合にのみ効果があります。

## このプロジェクトのアラートを許可 {#newProject-alert}

このプロジェクトのタスクに対してアラートを有効にします。アラートの送信先は、管理者がサーバー全体に対して設定します。メール、Telegram、Slack、Rocket.Chat、Microsoft Teams、DingTalk、Gotify のいずれかです。

- タスクが失敗すると、そのタスクを閲覧でき、かつ自分のアカウントでアラートを有効にしているプロジェクトのメンバーにメールが送信されます。
- タスクが成功したとき、失敗したとき、または確認待ちになったときに、メッセンジャーにメッセージが送信されます。

タスクテンプレートでは、成功したタスクまたは失敗したタスクがアラートを送信しないようにできます。

## Test Alerts {#settings-testAlerts}

サーバーで有効になっているすべてのチャネルを通じてテストアラートを送信し、このプロジェクトのアラートが届くことを確認できるようにします。

このボタンは、**このプロジェクトのアラートを許可** にチェックが入り、保存されている場合にのみ機能します。先にチェックを入れて **保存** を押してください。

## プロジェクトのバックアップ {#settings-exportProject}

プロジェクトの構成を含む JSON ファイルをダウンロードします。タスクテンプレート、インベントリ、リポジトリ、変数グループ、キー、スケジュール、統合、その他プロジェクトに設定されたものが含まれます。このファイルは、サイドバー上部のプロジェクトメニューにある **プロジェクトを復元** でプロジェクトに戻すことができます。

このファイルには、キーのシークレットと、変数グループの **Secrets** タブにあるシークレットは含まれません。これらは復元後に再度入力する必要があります。それ以外はすべてそのままコピーされ、ほかのフィールドに直接入力したパスワードも同様です。たとえば、パスワードを含むリポジトリのアドレス、静的インベントリのテキスト、通常の変数と環境変数の値です。ファイルを共有する前に、このような値が含まれていないか確認してください。タスクの履歴はバックアップに含まれません。

## キャッシュをクリア {#settings-clearCache}

Semaphore がこのプロジェクトのためにサーバー上に保持しているファイル (リポジトリのコピーなど) を削除します。これらは次のタスクの開始時に再度ダウンロードされます。

古くなった、または壊れたリポジトリのコピーが原因でタスクが失敗する場合に使います。この操作は元に戻せません。また、プロジェクトの設定には影響しません。

## プロジェクトを削除 {#settings-deleteProject}

プロジェクトを、その中のすべてのもの (タスクテンプレート、タスクの履歴、インベントリ、リポジトリ、変数グループ、キー、スケジュール) とともに削除します。Semaphore は最初に確認を求めます。

削除したプロジェクトは元に戻せません。再び必要になる可能性があるプロジェクトを削除する前に、バックアップをダウンロードしてください。
