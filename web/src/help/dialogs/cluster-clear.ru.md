# Clear tasks from Redis

Узлы кластера хранят общее состояние пула задач в Redis: какие задачи ждут, какие выполняются и
какой узел владеет каждой из них. Этот диалог удаляет из Redis отмеченные вами группы записей,
чтобы восстановить зависший кластер, например когда завершенная задача по-прежнему показана как
выполняемая. Из базы данных ничего не удаляется: задачи сохраняют свой статус, свой лог и свою
историю.

Что бы вы ни отметили, каждый узел также сбрасывает задачи, которые хранит в памяти, и заново
считывает их из Redis и базы данных. При открытии диалога отмечена только группа **Queue**;
отмечайте только те группы, которые зависли. В результате показывается, сколько записей удалено.

## Queue {#clusterClearDialog-queue}

Задачи, которые ждут, пока их запустит какой-либо узел. Удаленные из очереди задачи не
запускаются: они остаются в базе данных со статусом Waiting. Остановите их или запустите их
шаблоны снова.

## Running {#clusterClearDialog-running}

Задачи, которые кластер считает выполняемыми. Очистка не останавливает их: задача продолжает
выполняться на своем исполнителе. Но кластер теряет ее из виду: задача больше не учитывается в
лимитах параллельных задач сервера и своего исполнителя, поэтому может запуститься больше задач,
чем позволяют лимиты, а задача, которую исполнитель еще не взял, ему больше не передается.

## Active by project {#clusterClearDialog-active}

Незавершенные задачи каждого проекта. Они обеспечивают лимит параллельных задач проекта и не дают
запуститься второй задаче шаблона, пока выполняется первая, если шаблон не разрешает
параллельные задачи. Очистите эту группу, когда задачи проекта бесконечно ждут за задачами,
которые уже завершились. Задачи, выполняемые в этот момент, больше не учитываются, поэтому рядом с
ними могут запуститься новые задачи проекта.

## Aliases {#clusterClearDialog-aliases}

Случайные имена, которые задачи Terraform, OpenTofu и Terragrunt получают на время своей жизни,
сопоставленные с задачей. По этому имени выполняемая задача обращается к своему состоянию
Terraform на сервере: после очистки выполняемую задачу этих приложений по нему уже не найти.

## Claims {#clusterClearDialog-claims}

Какой узел владеет каждой задачей. Узел продлевает заявки на свои задачи каждую минуту; заявка,
которая не продлена, истекает через пять минут. Задача без заявки считается осиротевшей: задача,
которая еще не дошла до исполнителя, возвращается в очередь для другого узла, а задача, которую
исполнитель уже выполняет, остается там до завершения.

## Runtime fields {#clusterClearDialog-runtimeFields}

Сведения о каждой задаче, которых нет в базе данных: пользователь, который ее запустил, версия, с
которой она запущена, ее псевдоним, ее исполнитель и ее статус, а также проект каждой задачи. Без
них узел, который не запускал задачу, показывает о ней меньше, а очистка осиротевших задач
пропускает выполняемую задачу, так что зависшая запись больше не удаляется сама.
