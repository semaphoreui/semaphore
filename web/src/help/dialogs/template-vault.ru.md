# Хранилище

Хранилище передает Ansible пароль для файлов и переменных, зашифрованных с помощью Ansible Vault в
репозитории плейбуков. Каждое хранилище шаблона становится одним параметром `--vault-id` команды
`ansible-playbook`. Хранилище сохраняется вместе с шаблоном, когда вы сохраняете диалог шаблона.

## ID хранилища {#templateVaultDialog-name}

Необязательное поле. Vault ID, для которого предназначен пароль, — метка, с которой было
зашифровано содержимое (`ansible-vault encrypt --vault-id prod@prompt`). Оставьте поле пустым для
vault ID `default`.

ID сохраняется в нижнем регистре. Каждому хранилищу шаблона нужен собственный ID, и пустым может
быть только один.

## Тип {#templateVaultDialog-type}

Откуда берется пароль:

- **Пароль**: ключ из раздела «Хранилище ключей». Semaphore вводит его пароль, когда Ansible его
  запрашивает, поэтому пароль никогда не записывается в файл.
- **Клиентский скрипт**: клиентский скрипт пароля vault, который выводит пароль; его запускает
  Ansible.

## Пароль хранилища {#templateVaultDialog-vaultKeyId}

Показывается, когда выбран тип **Пароль**.

Ключ, в котором хранится пароль vault. В списке показаны только ключи типа **Логин с паролем**;
Semaphore использует их пароль и игнорирует логин. Поле обязательное.

## Путь к скрипту {#templateVaultDialog-script}

Показывается, когда выбран тип **Клиентский скрипт**.

Путь к скрипту, например `scripts/vault-pass-client.py`. Относительный путь отсчитывается от
каталога, в котором запускается Ansible: корня репозитория или рабочего каталога шаблона, если он
задан. Поле обязательное.

Имя файла должно заканчиваться на `-client`, с расширением или без: только тогда Ansible
запускает файл как клиентский скрипт и передает ему vault ID с помощью `--vault-id`. Скрипт
выполняется на машине, которая выполняет задачу, от имени пользователя, под которым работает
Semaphore.
