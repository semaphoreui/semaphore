# Редагувати виконавця

Виконавець — це окремий процес `semaphore runner`, який виконує завдання на власній машині, а не
на сервері Semaphore. Завдання потрапляє до виконавця, коли сервер налаштовано виконувати
завдання на виконавцях або коли шаблон завдання чи його інвентар має тег виконавця. Тоді сервер
вибирає виконавця, який увімкнений, зареєстрований, у мережі і не досяг свого ліміту паралельних
завдань: спершу виконавців проєкту, потім глобальних виконавців, у випадковому порядку в межах
кожної групи. Коли всі відповідні виконавці поза мережею або зайняті, завдання чекає в черзі;
коли не підходить жоден виконавець, завдання завершується з помилкою.

## Назва {#runner-name}

Обов’язкове поле. Назва, під якою виконавець відображається на сторінці «Виконавці», наприклад
хост, на якому він працює. Вона не впливає на те, які завдання отримує виконавець.

## Tags {#runner-tags}

Доступно в Semaphore Pro; в інших редакціях поле заблоковане.

Теги, за якими вибираються завдання цього виконавця. Завдання з тегом виконавця потрапляє лише до
виконавців, які мають цей тег; тег шаблону завдання має пріоритет над тегом інвентарю. Введіть тег
і натисніть Enter або виберіть тег, який використовують інші виконавці. Порожні й повторювані
теги відкидаються під час збереження.

Виконавцю проєкту потрібен принаймні один тег, якщо не встановлено **Is default**.

## Is default {#runner-isDefault}

Завдання без тегу виконавця потрапляє лише до виконавців, позначених як типові. Зніміть
прапорець для виконавця, який має брати лише завдання з одним із його тегів.

Для нового глобального виконавця прапорець установлено, для нового виконавця проєкту — знято.

## Register {#runner-registered}

Відображається, коли ви створюєте виконавця.

- Встановлено (за замовчуванням): сервер створює виконавця з його токеном. Після **Створити**
  діалог показує токен і команди, які запускають з ним виконавця.
- Знято: виконавця створюється без токена. Пізніше натисніть **Regenerate registration
  token** (іконка з двома стрілками) у рядку виконавця, щоб отримати одноразовий токен
  реєстрації, дійсний одну годину, і зареєструйте виконавця командою `semaphore runner register`.

Незареєстрований виконавець не отримує завдань.

## Webhook {#runner-webhook}

Необов’язкове поле. URL, який сервер викликає, коли передає завдання цьому виконавцю, наприклад
щоб запустити виконавця на вимогу. Сервер надсилає запит `POST` з тілом JSON:

```json
{"action": "start", "project_id": 1, "task_id": 42, "template_id": 7, "runner_id": 3}
```

URL має відповісти зі статусом 200 або 204 протягом 30 секунд; інакше завдання завершується з
помилкою. Виконавець із webhook завжди вважається таким, що в мережі, навіть якщо він давно не
опитував сервер. Залиште поле порожнім для виконавця, який працює постійно.

## Максимальна кількість паралельних завдань {#runner-maxParallelTasks}

Кількість завдань, які виконавець може виконувати одночасно. Коли ліміт досягнуто, наступне
завдання потрапляє до іншого відповідного виконавця або чекає в черзі. Залиште поле порожнім або
вкажіть `0`, щоб ліміту не було.

## Увімкнено {#runner-active}

Нові завдання отримує лише ввімкнений виконавець. Зніміть прапорець, щоб вивести виконавця з
роботи, не видаляючи його; перемикач у списку виконавців робить те саме.

Для нового виконавця прапорець знято: встановіть його або ввімкніть виконавця пізніше у списку.
