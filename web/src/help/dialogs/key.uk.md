# Редагувати Key

Ключ зі «Сховища ключів» містить облікові дані, які проєкт використовує, не показуючи їх:
SSH-ключ або пароль, з яким Ansible входить на хости, облікові дані Git-репозиторію, пароль
Ansible vault, секрет інтеграції. Інвентарі, репозиторії, шаблони завдань та інтеграції
посилаються на ключ за його назвою. Після збереження секрет ніколи не надсилається назад у
браузер.

## Ім’я ключа {#key-name}

Назва, під якою ключ відображається у «Сховищі ключів» і в списках вибору ключа в інвентарях,
репозиторіях, шаблонах завдань та інтеграціях. Поле обов’язкове. Оберіть назву, яка говорить, що
відкриває ключ, наприклад `Deploy key of the web servers`.

## Джерело {#key-source}

Де зберігається секрет ключа. Вкладки:

- **Local**: секрет вводиться в цьому діалозі і зберігається в базі даних Semaphore,
  зашифрований, якщо адміністратор задав ключ шифрування для ключів доступу. Це варіант за
  замовчуванням.
- **Storage**: секрет зберігається в зовнішньому сховищі секретів проєкту, вибраному в полі
  **Storage** нижче. Ця вкладка є лише в редакції Pro. Самі сховища налаштовуються на вкладці
  **Storages** «Сховища ключів».
- **Env**: секрет зчитується зі змінної середовища процесу сервера Semaphore. Введіть назву
  змінної в полі під вкладками.
- **File**: секрет зчитується з файлу на сервері Semaphore. Введіть абсолютний шлях до файлу в
  полі під вкладками. Файл має бути всередині каталогу секретів сервера (`dirs.secrets` у його
  конфігурації, за замовчуванням `/tmp/semaphore`); шлях поза ним або шлях, що містить `..`,
  призводить до помилки під час використання ключа. Кінцевий розрив рядка у файлі відкидається.

З **Env** і **File** Semaphore ніколи не записує секрет: він зчитує значення щоразу, коли завдання
використовує ключ, тож змінюйте секрет там, де він зберігається. Значення має відповідати полю
**Тип** ключа. Ключ **Рядок** бере значення як є. Ключ **SSH-ключ** або **Логін з паролем** очікує
JSON з полями цього типу, наприклад:

```json
{"login": "deploy", "password": "s3cret"}
```

```json
{"login": "deploy", "passphrase": "", "private_key": "-----BEGIN OPENSSH PRIVATE KEY-----\n..."}
```

Під час редагування ключа вкладки заблоковані, доки не встановлено прапорець **Перезаписати**.
Ключ, синхронізований зі сховища секретів, зберігає своє джерело, а його назву і тип змінити не
можна.

## Storage {#key-sourceStorageId}

Відображається, коли вибрано вкладку **Storage**.

Сховище секретів проєкту, яке містить секрет: HashiCorp Vault, OpenBao, Devolutions Server, AWS
Secrets Manager або Azure Key Vault, налаштоване на вкладці **Storages** «Сховища ключів».

- Сховище, яке не є лише для читання, отримує секрет, який ви вводите в цьому діалозі: Semaphore
  записує його туди під час збереження. Видалення ключа видаляє секрет і зі сховища. Ключ, що
  зберігається в такому сховищі, згодом не можна перенести в інше сховище.
- Сховище лише для читання тільки читається. Діалог тоді не показує полів для секрету, а
  Semaphore зчитує його зі сховища щоразу, коли завдання використовує ключ.

## Source Key {#key-sourceStorageKey}

Відображається, коли вибрано **Storage**.

Де в цьому сховищі розміщено секрет, наприклад шлях до секрету в HashiCorp Vault.

## Тип {#key-type}

Який вид облікових даних містить ключ. Поле обов’язкове, а поля під ним змінюються залежно від
типу.

- **SSH-ключ**: приватний ключ з необов’язковим логіном і парольною фразою. Ansible під’єднується
  з ним до хостів, а Git клонує з ним репозиторій з URL `ssh`.
- **Логін з паролем**: логін і пароль. Ansible під’єднується з ними до хостів або стає з ними
  іншим користувачем (**Облікові дані sudo** інвентарю); Git клонує з ними репозиторій `https`;
  пароль відкриває Ansible vault шаблону завдання.
- **Рядок**: одне секретне значення без логіна: токен, API-ключ, пароль. Використовуйте його для
  секрету інтеграції. Він не може бути SSH-ключем, обліковими даними sudo, паролем vault або
  ключем доступу репозиторію.
- **Немає**: без облікових даних. Використовуйте його для репозиторію, якому не потрібен вхід
  (публічний репозиторій `https`, URL `file` або локальний шлях), і для інвентарю, хостам якого не
  потрібні облікові дані або які самі визначають з’єднання.

## Ім'я користувача {#key-loginPasswordLogin}

Відображається, коли вибрано тип **Логін з паролем**. Необов’язкове поле.

Ім’я користувача облікових даних.

- Ansible під’єднується до хостів від імені цього користувача (`--user`); в **Облікові дані sudo**
  інвентарю це користувач, яким стає Ansible (`--become-user`). Коли поле порожнє, Ansible
  використовує користувача, вказаного в інвентарі або у власній конфігурації Ansible.
- Для репозиторію `https` Git входить з цим користувачем і паролем. Залиште поле порожнім для
  токена, який Git-сервер приймає окремо: тоді пароль надсилається як ім’я користувача.

## Пароль {#key-loginPasswordPassword}

Відображається, коли вибрано тип **Логін з паролем**. Обов’язкове поле.

Пароль облікових даних. Semaphore відповідає ним на запити пароля від Ansible: пароль SSH
(`--ask-pass`) для облікових даних користувача, пароль `become` (`--ask-become-pass`) для
облікових даних sudo і пароль vault для Ansible vault. Для репозиторію `https` це пароль або
токен доступу Git-сервера.

## Значення {#key-stringValue}

Відображається, коли вибрано тип **Рядок**. Обов’язкове поле.

Саме секретне значення, наприклад токен, за яким інтеграція перевіряє отримані запити.
Зберігається так, як його введено.

## Ім'я користувача {#key-sshLogin}

Відображається, коли вибрано тип **SSH-ключ**. Необов’язкове поле.

Користувач, від імені якого Ansible під’єднується до хостів (`--user`). Коли поле порожнє, Ansible
використовує користувача, вказаного в інвентарі або у власній конфігурації Ansible.

Для Git-репозиторію натомість вкажіть користувача в URL репозиторію, як у
`git@github.com:org/repo.git`.

## Passphrase {#key-sshPassphrase}

Відображається, коли вибрано тип **SSH-ключ**. Необов’язкове поле.

Парольна фраза, якою зашифровано приватний ключ. Залиште поле порожнім для ключа без парольної
фрази. Неправильна парольна фраза призводить до помилки кожного завдання, яке використовує ключ,
під час завантаження ключа. Ключ, згенерований Semaphore, не має парольної фрази: вміст цього поля
тоді відкидається.

## Generate SSH Key {#key-generateSshKey}

Відображається, коли вибрано тип **SSH-ключ**.

Під час збереження Semaphore створює нову пару ключів: 2048-бітний приватний ключ RSA, який
залишається в ключі, і його публічний ключ, який показується один раз у діалозі після збереження,
а потім у **Public key** щоразу, коли ви редагуєте ключ. Додайте публічний ключ до
`~/.ssh/authorized_keys` на хостах або як deploy key Git-репозиторію.

Поле приватного ключа заблоковане, поки встановлено прапорець. Для наявного ключа спершу
встановіть **Перезаписати**: стару пару ключів буде замінено. Ключ, секрет якого зчитується з
**Env**, **File** або сховища лише для читання, згенерувати не можна, бо Semaphore нікуди його
записати.

## Приватний ключ {#key-sshPrivateKey}

Відображається, коли вибрано тип **SSH-ключ**. Обов’язкове поле, якщо не встановлено
**Generate SSH Key**.

Приватний ключ у форматі OpenSSH або PEM, разом із рядками `BEGIN` і `END`. Для завдання
Semaphore завантажує його у власний SSH-агент, яким Ansible і Git користуються протягом
завдання.

## Public key {#key-publicKey}

Відображається, коли ви редагуєте SSH-ключ, згенерований Semaphore, поки не встановлено
**Перезаписати**.

Публічна половина згенерованої пари ключів. **Show** розгортає її, кнопка копіювання поміщає її в
буфер обміну. Додайте її до `~/.ssh/authorized_keys` на хостах або як deploy key Git-репозиторію.

Це публічний ключ пари, яку Semaphore згенерував останньою. Після того як ви вручну заміните
приватний ключ за допомогою **Перезаписати**, показаний тут ключ йому більше не відповідає.

## Перезаписати {#key-overrideSecret}

Відображається, коли ви редагуєте наявний ключ.

Semaphore ніколи більше не показує збережений секрет, тож поля секрету порожні й заблоковані.
Встановіть прапорець, щоб замінити секрет: джерело, тип і поля секрету відкриваються, і все в них
зберігається заново, тож введіть увесь секрет знову, а не лише ту частину, що змінюється. Без
нього збереження змінює лише назву ключа.

Збереження ключа також видаляє копії репозиторіїв, які його використовують, що їх зберігає сервер
Semaphore: наступне завдання клонує їх знову.
