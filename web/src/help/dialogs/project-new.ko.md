# 새 프로젝트

프로젝트는 하나의 업무에 필요한 작업 템플릿, 인벤토리, 리포지토리, 변수 그룹, 키와 그 업무를 하는 사람들을
담습니다. 프로젝트를 만든 사람은 그 프로젝트의 소유자가 됩니다. 서버 관리자가 모든 사용자에게 허용하지
않는 한, 관리자만 프로젝트를 만들 수 있습니다. 아래의 모든 설정은 나중에 프로젝트의 설정 페이지에서 변경할
수 있습니다.

## 프로젝트 이름 {#newProject-name}

사이드바 상단의 프로젝트 메뉴에 표시되는 프로젝트 이름입니다. 이 필드는 필수입니다.

## 최대 병렬 작업 수 {#newProject-maxParallelTasks}

이 프로젝트의 작업을 동시에 몇 개까지 실행할 수 있는지 지정합니다. 한도를 넘어 시작된 작업은 실행 중인
작업 중 하나가 끝날 때까지 대기열에서 기다립니다.

프로젝트 자체의 한도를 두지 않으려면 이 필드를 비워 두거나 `0`으로 설정하세요. 어느 경우든 관리자가 설정한
서버 전체의 한도가 적용됩니다.

## 텔레그램 채팅 ID {#newProject-tg}

선택 사항입니다. 이 프로젝트의 알림을 받을 Telegram 채팅입니다. 이 필드가 비어 있으면 알림은 서버 전체에
설정된 채팅으로 전송됩니다.

이 필드는 관리자가 서버에서 Telegram 알림을 켜고, 이 프로젝트에 알림이 허용된 경우에만 효과가 있습니다.

## 이 프로젝트에 대한 알림 허용 {#newProject-alert}

이 프로젝트의 작업에 대해 알림을 켭니다. 알림이 전송되는 곳은 관리자가 서버 전체에 대해 설정합니다.
이메일, Telegram, Slack, Rocket.Chat, Microsoft Teams, DingTalk 또는 Gotify입니다.

- 작업이 실패하면 해당 작업을 볼 수 있고 자신의 계정에서 알림을 켠 프로젝트 멤버에게 이메일이 전송됩니다.
- 작업이 성공하거나, 실패하거나, 확인을 기다릴 때 메신저로 메시지가 전송됩니다.

## Demo {#newProject-demo}

Semaphore를 사용해 볼 수 있는 예제로 새 프로젝트를 채웁니다. 공개 리포지토리
`https://github.com/semaphoreui/semaphore-demo.git`, 인벤토리, vault 비밀번호 키, 그리고 Ansible, OpenTofu,
Terragrunt, Bash, PowerShell용 작업 템플릿이 **Build**, **Deploy**, **Tools** 보기로 분류되어 들어갑니다.

예제 없는 프로젝트를 원하면 스위치를 끈 채로 두세요. 그러면 프로젝트에는 **None** 키와 **All** 보기만
생깁니다. 예제는 프로젝트의 일반 항목이므로 원하는 대로 수정하거나 삭제할 수 있습니다.
