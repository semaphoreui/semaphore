# ユーザーを編集

ユーザーは、Semaphore にサインインするアカウントです。**Settings** タブにはアカウントのプロフィールとフラグがあり、**保存** でそれらを書き込みます。**Security** タブにはパスワード、2 要素認証、リンクされたサインインアカウントがあり、**Roles** タブにはユーザーのグローバルロールがあります。どちらのタブも **保存** なしですぐに反映されます。ユーザーがプロジェクト内で行えることは、ここではなく、そのプロジェクトの **チーム** ページで設定します。

## 名前 {#user-name}

サイドバー、およびユーザーとプロジェクトのメンバーの一覧に表示される、ユーザーのフルネームです。このフィールドは必須です。

**外部** ユーザーの場合、ID プロバイダーが名前を送信すると、Semaphore はサインイン時にそこから名前を取得します。そのため、ここで行った変更は次回のサインイン以降は残らないことがあります。

## ユーザー名 {#user-username}

ユーザーのログインです。このフィールドは必須です。ユーザーは、ユーザー名またはメールと、パスワードでサインインします。

**外部** ユーザーのユーザー名は変更できません。サーバーは保存を拒否します。

## メール {#user-email}

ユーザーのメールアドレスです。このフィールドは必須です。Semaphore はユーザーのタスクのアラートをこのアドレスに送信し、認証アプリはこれをアカウントの名前として表示します。これは非公開で、ユーザー本人とユーザーを管理できる人だけが見られます。

**外部** ユーザーの場合、メールは ID プロバイダーから取得されます。このフィールドは読み取り専用で、Semaphore はサインインのたびにアドレスを更新します。

## パスワード {#user-password}

新しいユーザーを作成する場合に表示されます。

ユーザーがサインインに使うパスワードです。このフィールドは必須ですが、Semaphore にパスワードを持たない **外部** ユーザーの場合は除きます。既存のユーザーのパスワードを変更するには、**Security** タブの **Change password** を使います。

## アラートを送信 {#user-alert}

ユーザーがタスクを表示できるプロジェクトでタスクが失敗したときに、ユーザーにメールを送信します。プロジェクトがアラートを許可していて、サーバーの管理者がメールのアラートを有効にしている必要があります。タスクテンプレートでは、失敗したタスクがアラートを送信しないようにできます。

このフラグは、Telegram、Slack、その他のメッセンジャーに送信されるプロジェクトのアラートには影響しません。

## 管理者ユーザー {#user-admin}

自分が管理者の場合に表示されます。

管理者はサーバー上ですべてのことを行えます。ユーザー、グローバルロール、サーバーの設定を管理し、すべてのプロジェクトを完全な権限で開けます。

自分のアカウントからこのフラグを外すことはできません。また、サーバーは少なくとも 1 人の管理者を保持するため、最後の管理者からフラグを外すことを拒否します。

## Pro user {#user-pro}

Pro エディションで表示されます。このフラグを変更できるのは管理者だけです。

ユーザーに Pro サブスクリプションの枠を割り当てます。サブスクリプションの Pro ユーザーの数は決まっています。上限に達すると、サーバーはフラグの保存を拒否します。有効なサブスクリプションがない場合、このフラグは効果がありません。

## 外部 {#user-external}

自分が管理者の場合に表示されます。ユーザーを作成するときにのみ設定できます。

外部ユーザーは、Semaphore のパスワードではなく、LDAP または OpenID Connect でサインインします。パスワードのフィールドは無効になり、パスワードでのサインインは拒否されます。名前とメールは、サインインのたびに ID プロバイダーから取得されます。パスワードでサインインするユーザーでは、チェックを外したままにします。

## Change password {#user-changePassword}

**外部** ではない既存のユーザーの **Security** タブで、サーバーがパスワードでのサインインを許可している場合に表示されます。

新しいパスワードを設定するダイアログを開きます。自分のパスワードを変更するには、現在のパスワードを入力する必要があります。他のユーザーのパスワードをリセットする場合は不要です。

## Time-based one-time password {#user-totp}

管理者がサーバーで 2 要素認証を有効にしている場合に、**Security** タブに表示されます。

このユーザーの 2 要素認証を有効にします。スイッチをオンにすると、Semaphore はすぐにシークレットを作成し、QR コードとして表示します。認証アプリでスキャンしてください。それ以降、サインインではパスワードの後にアプリのコードが求められます。

サーバーが回復を許可している場合、QR コードの下に回復コードが表示されます。これは一度だけ表示されます。コピーして安全に保管してください。スイッチをオフにすると、シークレットはすぐに削除されます。

## LDAP provider {#user-ldapProvider}

サーバーに、自分のアカウントがまだリンクされていない LDAP プロバイダーがある場合に、自分のアカウントの **Security** タブに表示されます。

複数ある場合に、自分のアカウントをリンクする LDAP サーバーです。

## LDAP username {#user-ldapUsername}

**LDAP provider** とともに表示されます。

LDAP サーバーでの自分のユーザー名です。リンクすると、このアカウントに LDAP でもサインインできるようになります。

## LDAP password {#user-ldapPassword}

**LDAP provider** とともに表示されます。

LDAP サーバーでの自分のパスワードです。Semaphore は LDAP のアカウントが自分のものであることを確認するために一度だけ使い、保存しません。

## Link {#user-ldapLink}

**LDAP provider** とともに表示されます。

自分のアカウントを上の LDAP のアカウントにリンクします。資格情報が間違っている場合、LDAP のアカウントが別のユーザーにリンクされている場合、または自分のアカウントがすでにそのプロバイダーにリンクされている場合、リンクは拒否されます。リンクされたアカウントは **Linked accounts** の下に表示されます。リンクを解除するには、そのチップを閉じます。

## Global role {#global-role-select}

Pro エディションで、グローバルロールを管理できる場合に、既存のユーザーの **Roles** タブに表示されます。

ユーザーがまだ持っていないロールの中から、ユーザーに付与するグローバルロールです。グローバルロールは、サーバー全体に対する権限を付与します。ユーザー、グローバルロール、サーバーの設定の管理、または監査ログの閲覧です。グローバルロール自体は、ユーザー ページの **グローバルロール** タブで作成します。

## Assign {#globalRoleAssign-assign}

**Global role** とともに表示されます。

選択したロールをすぐにユーザーに付与します。ユーザーが持つロールは下に一覧表示され、それぞれにロールを取り消すボタンがあります。**Effective global permissions** は、ユーザーが最終的に行えることと、各権限の由来を表示します。
