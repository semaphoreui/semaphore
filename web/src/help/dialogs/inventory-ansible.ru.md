# Редактировать Ansible Inventory

Инвентарь сообщает Ansible, на каких хостах запускать плейбук, и хранит учетные данные, с которыми
Semaphore к ним подключается. Шаблон задачи ссылается на инвентарь, и каждая задача этого шаблона
выполняется на его хостах. Формат инвентаря описан в
[руководстве Ansible по инвентарю](https://docs.ansible.com/ansible/latest/inventory_guide/intro_inventory.html).

## Имя {#inventoryForm-name}

Имя, под которым инвентарь показан на странице «Инвентарь» и в списке выбора инвентаря в шаблоне
задачи. Выберите имя, по которому наборы хостов легко различить, например `Production web servers`.

## Тег исполнителя {#inventoryForm-runnerTag}

Показывается, когда в проекте доступны исполнители.

Задачи, использующие этот инвентарь, выполняются на исполнителе с этим тегом. Тег исполнителя,
заданный в шаблоне задачи, имеет приоритет над тегом инвентаря. Оставьте поле пустым, чтобы задачи
мог взять любой исполнитель.

## Учетные данные пользователя {#inventoryForm-sshKeyId}

Ключ из раздела «Хранилище ключей», с которым Ansible входит на хосты. Поле обязательное и
принимает ключи трех типов:

- **SSH ключ**: Ansible подключается с закрытым ключом и, если у ключа есть логин, с этим логином.
- **Логин с паролем**: Ansible подключается с логином и паролем.
- **Нет**: Semaphore не передает никаких учетных данных. Используйте этот тип для хостов, которым
  они не нужны, например `localhost`, или когда способ подключения задан в самом инвентаре.

## Учетные данные sudo {#inventoryForm-becomeKeyId}

Необязательное поле. Ключ типа **Логин с паролем** из раздела «Хранилище ключей», который
используется, когда play повышает привилегии с помощью `become`: его логин — это пользователь, от
имени которого действует Ansible, а его пароль — это пароль, который Ansible вводит в ответ на
запрос.

Оставьте поле пустым, если play не повышают привилегии или если указанному выше пользователю для
этого не нужен пароль.

## Тип {#inventoryForm-type}

Откуда берется инвентарь:

- **Static**: инвентарь вводится в этом диалоге в формате INI.
- **Static YAML**: инвентарь вводится в этом диалоге в формате YAML. Используйте этот тип и для
  конфигурации плагина инвентаря.
- **File**: инвентарь — это файл в Git-репозитории.
- **Managed**: хосты и их переменные хранятся как записи. Чтобы изменить их, откройте инвентарь из
  списка.

Поля под типом меняются вместе с ним.

## Путь к файлу инвентаря {#inventoryForm-inventoryPath}

Показывается, когда выбран тип **File**.

Путь к файлу инвентаря от корня его репозитория, например `inventory/production.yml`. Это
репозиторий, выбранный в поле «Репозиторий», а если это поле пустое — репозиторий шаблона задачи,
который использует инвентарь.

## Репозиторий {#inventoryForm-repositoryId}

Показывается, когда выбран тип **File**. Необязательное поле.

Репозиторий, в котором лежит файл инвентаря. Semaphore обновляет свою копию репозитория перед
каждой задачей. Оставьте поле пустым, если файл находится в том же репозитории, что и плейбук:
тогда путь ищется в репозитории шаблона задачи.

## Инвентарь {#inventoryForm-inventoryCode}

Показывается, когда выбран тип **Static** или **Static YAML**.

Текст инвентаря. Semaphore хранит его и для каждой задачи записывает во временный файл.
Статический инвентарь в формате INI:

```ini
[web]
10.0.0.11
10.0.0.12

[db]
10.0.0.21 ansible_port=2222
```

Те же хосты в формате **Static YAML**:

```yaml
web:
  hosts:
    10.0.0.11:
    10.0.0.12:
db:
  hosts:
    10.0.0.21:
      ansible_port: 2222
```
