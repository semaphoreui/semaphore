# Редагувати запуск

Запуск — це те, що інтеграція запускає, коли інший сервіс звертається до webhook URL Semaphore,
наприклад під час події push у GitHub: завдання шаблону завдання або workflow. URL і перевірка
запиту належать до ендпоінта інтеграції, а не до запуску. На сторінці запуску містяться його умови
та значення, які він бере із запиту.

## Назва {#integrationForm-name}

Назва, під якою інтеграція відображається на сторінці «Інтеграції». Завдання, які запускає
інтеграція, приписуються їй у журналі аудиту. Поле обов’язкове.

## Інтеграція {#integrationForm-groupId}

Інтеграція, до якої належить запуск. Запуск спрацьовує на запити, які надходять на ендпоінт цієї
інтеграції та проходять її авторизацію. Поле обов'язкове.

## Ціль {#integrationForm-targetToggle}

Відображається, коли сервер підтримує workflow.

Що запускає інтеграція: **Template** запускає завдання шаблону завдання, **Workflow** запускає
виконання workflow. Перемикання на **Workflow** скидає параметри завдання нижче.

## Workflow to run {#integrationForm-workflowId}

Відображається, коли в полі **Ціль** вибрано **Workflow**.

Workflow, який запускає запит. Кожне значення, яке інтеграція бере із запиту, передається
workflow як відповідь на його змінну опитування з такою самою назвою. Інтеграції з workflow
потребують редакції Pro: без неї поле неактивне, а сервер відхиляє зміну.

## Шаблон завдання для запуску {#integrationForm-templateId}

Відображається, коли в полі **Ціль** вибрано **Template**.

Шаблон завдання, завдання якого запускає запит. Поле обов’язкове. Щойно шаблон вибрано, під ним
з’являються параметри його завдань.

## Параметри завдання {#integrationForm-taskParams}

Відображається, коли вибрано шаблон завдання.

Параметри, які отримує кожне завдання, запущене цією інтеграцією, так, ніби ви запустили його з
шаблону самі. Тут є лише ті опції, які шаблон дозволяє перевизначати в завданні. Значення, взяті
із запиту, перевизначають їх: значення типу **Variables** — відповідь з такою самою назвою,
значення типу **Task Params** — параметр з такою самою назвою.

Коли шаблон дозволяє CLI-аргументи в завданні, **CLI args** містить додаткові аргументи для
командного рядка завдання.

## Повідомлення {#taskParams-message}

Необов’язкове поле. Повідомлення кожного завдання, яке запускає інтеграція, що відображається в
історії завдань.

## Змінні опитування {#taskParams-survey}

Відображається, коли шаблон має змінні опитування.

Відповіді на опитування шаблону, однакові для кожного завдання. Значення типу **Variables**, взяте
із запиту, замінює відповідь з такою самою назвою.

Відповіді на змінні типу secret не зберігаються разом з інтеграцією: передавайте секрет через
групу змінних шаблону.

## Гілка {#taskParams-gitBranch}

Відображається, коли шаблон дозволяє перевизначати гілку в завданні.

Гілка або тег репозиторію, які завдання отримують з репозиторію. Залиште значення як є, щоб
використати гілку шаблону. Значення з назвою `git_branch` типу **Task Params**, взяте із запиту,
перевизначає його; початкове `refs/heads/` у цьому значенні видаляється.

## Інвентар {#taskParams-inventoryId}

Відображається, коли шаблон дозволяє перевизначати інвентар у завданні.

Інвентар, а для Terraform — workspace, з яким виконуються завдання замість інвентарю шаблону.

## Опції Ansible {#taskParams-ansible}

Відображається, коли шаблон запускає Ansible playbook.

Опції `ansible-playbook` для кожного завдання, кожна з яких відображається, коли шаблон її
дозволяє: **Обмеження**, **Теги**, **Пропустити теги**, **Налагодження**, **Тестовий запуск**
(`--check`), **Порівняння** і **Skip Galaxy install**.

## Опції Terraform {#taskParams-terraform}

Відображається, коли шаблон запускає Terraform, OpenTofu або Terragrunt.

- **Plan**: завдання виконує план і зупиняється, нічого не застосовується.
- **Destroy**: план і застосування знищують ресурси.
- **Auto Approve**: план застосовується без підтвердження, коли шаблон дозволяє автоматичне
  підтвердження. Без цього завдання чекає, доки хтось не підтвердить його в Semaphore.
- **Upgrade** і **Reconfigure**: `init` виконується з `-upgrade` і `-reconfigure`.
