# Редагувати Repository

Репозиторій — це місце, звідки беруться playbook, код Terraform або скрипти шаблону завдання:
Git-репозиторій або каталог на машині, яка виконує завдання. Перед кожним завданням Semaphore
клонує Git-репозиторій або оновлює копію, клоновану раніше, перемикається на гілку і виконує
завдання в цій копії.

## Назва {#repository-name}

Назва, під якою репозиторій відображається на сторінці «Репозиторії» і в списку вибору
репозиторію шаблону завдання та інвентарю. Поле обов’язкове.

## URL або шлях {#repository-gitUrl}

Де розміщено код. Поле обов’язкове. Чипи під полем показують вид введеної адреси, а клік на чипі
переписує адресу в цей вид.

- **ssh**: `git@github.com:org/repo.git` або `ssh://git@github.com/org/repo.git`. Git входить з
  користувачем з адреси і **SSH-ключ**, вибраним у полі **Ключ доступу**.
- **https** і **http**: `https://github.com/org/repo.git`. Приватному репозиторію потрібен ключ
  **Логін з паролем**; публічному — **Немає**. Уникайте `http`: логін і пароль тоді передаються
  незашифрованими.
- **git**: `git://host/org/repo.git`, протокол Git лише для читання, без входу.
- **file**: `file:///srv/git/repo.git`, Git-репозиторій на диску машини, яка виконує завдання,
  що клонується як віддалений.
- **абс. шлях**: абсолютний шлях, наприклад `/srv/playbooks` або `D:\playbooks`. Semaphore його не
  клонує: завдання виконується безпосередньо в цьому каталозі, який має існувати на машині, що
  виконує завдання (сервері Semaphore або виконавці). Гілка до нього не застосовується.

Зміна адреси видаляє копії, які сервер Semaphore клонував зі старої адреси.

## Гілка {#repository-gitBranch}

Гілка, яку Semaphore клонує і підтримує в актуальному стані, наприклад `main`. Поле обов’язкове,
крім абсолютного шляху, для якого воно заблоковане.

Шаблон завдання може вказати власну гілку, яка має пріоритет над цією, а шаблон може дозволити
своїм завданням вибирати гілку під час запуску. Тег теж працює, але тег не можна оновити через
pull, тож Semaphore клонує репозиторій заново перед кожним завданням.

## Single checkout for all templates {#repository-monorepo}

За замовчуванням вимкнено: кожен шаблон завдання отримує власну копію репозиторію. Встановіть
прапорець, щоб клонувати репозиторій один раз і спільно використовувати цю копію в усіх шаблонах,
які її використовують, — для репозиторію, надто великого, щоб тримати копію на кожен шаблон.

Спільна копія залишається на гілці цього репозиторію: шаблони, що її використовують, не можуть
мати власної гілки, а їхні завдання не можуть вибрати іншу гілку чи коміт. Заблоковано для
абсолютного шляху.

## Ключ доступу {#repository-sshKeyId}

Ключ зі «Сховища ключів», з яким Git входить до репозиторію. Поле обов’язкове. Воно пропонує ключі
трьох типів, вибір залежить від URL:

- **SSH-ключ** для URL `ssh`. Semaphore завантажує приватний ключ в SSH-агент на час клонування
  або оновлення. Користувач — той, що в URL, як `git` у `git@github.com:org/repo.git`.
- **Логін з паролем** для URL `https`: логін і пароль або токен доступу Git-сервера. З порожнім
  логіном пароль надсилається окремо, як ім’я користувача, чого деякі сервери очікують від
  токена. Ті самі облікові дані передаються `ansible-galaxy` для ролей і колекцій на тому самому
  сервері.
- **Немає** для публічного репозиторію, URL `git` або `file` чи абсолютного шляху.

Ключ, який не відповідає URL, не дає Git облікових даних, і тоді приватний репозиторій не
вдається клонувати.
