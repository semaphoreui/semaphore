# 수정 Key

키 저장소의 키는 프로젝트가 드러내지 않고 사용하는 자격 증명을 보관합니다. Ansible이 호스트에 로그인할 때
쓰는 SSH 키나 비밀번호, Git 리포지토리의 자격 증명, Ansible vault의 비밀번호, 통합의 시크릿 등이 해당합니다.
인벤토리, 리포지토리, 작업 템플릿, 통합은 이름으로 키를 참조합니다. 한 번 저장된 비밀 값은 브라우저로 다시
전송되지 않습니다.

## 키 이름 {#key-name}

키 저장소와 인벤토리, 리포지토리, 작업 템플릿, 통합의 키 선택 목록에 표시되는 키 이름입니다. 이 필드는
필수입니다. 키가 무엇을 여는지 알 수 있는 이름을 지정하세요. 예: `Deploy key of the web servers`.

## 소스 {#key-source}

키의 비밀 값이 보관되는 위치입니다. 탭은 다음과 같습니다.

- **Local**: 비밀 값을 이 대화 상자에 입력하며 Semaphore 데이터베이스에 저장됩니다. 관리자가 액세스 키용
  암호화 키를 설정한 경우 암호화됩니다. 기본값입니다.
- **Storage**: 비밀 값은 아래 **Storage**에서 선택한 프로젝트의 외부 비밀 저장소에 보관됩니다. 이 탭은 Pro
  에디션에만 있습니다. 저장소 자체는 키 저장소의 **Storages** 탭에서 설정합니다.
- **Env**: 비밀 값을 Semaphore 서버 프로세스의 환경 변수에서 읽습니다. 탭 아래의 필드에 변수 이름을
  입력하세요.
- **File**: 비밀 값을 Semaphore 서버의 파일에서 읽습니다. 탭 아래의 필드에 파일의 절대 경로를 입력하세요.
  파일은 서버의 비밀 디렉터리(구성의 `dirs.secrets`, 기본값 `/tmp/semaphore`) 안에 있어야 합니다. 그 밖의
  경로나 `..`이 들어 있는 경로는 키를 사용할 때 실패합니다. 파일 끝의 줄 바꿈은 제거됩니다.

**Env**와 **File**의 경우 Semaphore는 비밀 값을 기록하지 않습니다. 작업이 키를 사용할 때마다 값을 읽으므로,
비밀 값은 그것이 있는 곳에서 변경합니다. 값은 키의 **유형**에 맞아야 합니다. **문자열** 키는 값을 그대로
사용합니다. **SSH 키**나 **비밀번호로 로그인** 키는 해당 유형의 필드가 담긴 JSON을 기대합니다. 예:

```json
{"login": "deploy", "password": "s3cret"}
```

```json
{"login": "deploy", "passphrase": "", "private_key": "-----BEGIN OPENSSH PRIVATE KEY-----\n..."}
```

키를 수정할 때는 **재정의**를 체크할 때까지 탭이 잠겨 있습니다. 비밀 저장소에서 동기화된 키는 소스를
유지하며, 이름과 유형을 바꿀 수 없습니다.

## Storage {#key-sourceStorageId}

**Storage** 탭을 선택했을 때 표시됩니다.

비밀 값을 보관하는 프로젝트의 비밀 저장소입니다. 키 저장소의 **Storages** 탭에서 설정한 HashiCorp Vault,
OpenBao, Devolutions Server, AWS Secrets Manager 또는 Azure Key Vault입니다.

- 읽기 전용이 아닌 저장소는 이 대화 상자에 입력한 비밀 값을 받습니다. 저장할 때 Semaphore가 그곳에
  기록합니다. 키를 삭제하면 저장소의 비밀 값도 삭제됩니다. 이런 저장소에 보관된 키는 나중에 다른 저장소로
  옮길 수 없습니다.
- 읽기 전용 저장소는 읽기만 합니다. 이 경우 대화 상자에는 비밀 값 필드가 표시되지 않으며, Semaphore는
  작업이 키를 사용할 때마다 저장소에서 비밀 값을 읽습니다.

## Source Key {#key-sourceStorageKey}

**Storage**를 선택했을 때 표시됩니다.

그 저장소에서 비밀 값이 있는 위치입니다. 예: HashiCorp Vault에서 비밀 값의 경로.

## 유형 {#key-type}

키가 보관하는 자격 증명의 종류입니다. 이 필드는 필수이며, 유형에 따라 그 아래의 필드가 바뀝니다.

- **SSH 키**: 개인 키이며, 로그인과 암호 문구는 선택 사항입니다. Ansible은 이 키로 호스트에 연결하고, Git은
  이 키로 `ssh` URL의 리포지토리를 복제합니다.
- **비밀번호로 로그인**: 로그인과 비밀번호입니다. Ansible은 이것으로 호스트에 연결하거나 다른 사용자로
  전환합니다(인벤토리의 **Sudo 자격 증명**). Git은 이것으로 `https` 리포지토리를 복제하며, 비밀번호는 작업
  템플릿의 Ansible vault를 엽니다.
- **문자열**: 로그인 없는 단일 비밀 값입니다. 토큰, API 키, 비밀번호 등입니다. 통합의 시크릿에 사용하세요.
  SSH 키, sudo 자격 증명, vault 비밀번호, 리포지토리의 액세스 키로는 사용할 수 없습니다.
- **없음**: 자격 증명이 없습니다. 로그인이 필요 없는 리포지토리(공개 `https` 리포지토리, `file` URL 또는
  로컬 경로)와, 호스트에 자격 증명이 필요 없거나 호스트가 연결 방법을 직접 정의하는 인벤토리에 사용하세요.

## 사용자 이름 {#key-loginPasswordLogin}

유형이 **비밀번호로 로그인**일 때 표시됩니다. 선택 사항입니다.

자격 증명의 사용자 이름입니다.

- Ansible은 이 사용자로 호스트에 연결합니다(`--user`). 인벤토리의 **Sudo 자격 증명**으로 사용하면 Ansible이
  전환할 사용자입니다(`--become-user`). 이 필드가 비어 있으면 Ansible은 인벤토리나 자체 구성에 지정된
  사용자를 사용합니다.
- `https` 리포지토리의 경우 Git은 이 사용자와 비밀번호로 로그인합니다. Git 서버가 토큰만으로 받아들이는
  경우 비워 두세요. 그러면 비밀번호가 사용자 이름으로 전송됩니다.

## 비밀번호 {#key-loginPasswordPassword}

유형이 **비밀번호로 로그인**일 때 표시됩니다. 필수입니다.

자격 증명의 비밀번호입니다. Semaphore는 이 비밀번호로 Ansible의 비밀번호 프롬프트에 응답합니다. 사용자
자격 증명에는 SSH 비밀번호(`--ask-pass`), sudo 자격 증명에는 `become` 비밀번호(`--ask-become-pass`),
Ansible vault에는 vault 비밀번호입니다. `https` 리포지토리의 경우 Git 서버의 비밀번호나 액세스 토큰입니다.

## 값 {#key-stringValue}

유형이 **문자열**일 때 표시됩니다. 필수입니다.

비밀 값 자체입니다. 예: 통합이 받은 요청을 확인할 때 사용하는 토큰. 입력한 그대로 저장됩니다.

## 사용자 이름 {#key-sshLogin}

유형이 **SSH 키**일 때 표시됩니다. 선택 사항입니다.

Ansible이 호스트에 연결할 때 사용하는 사용자입니다(`--user`). 이 필드가 비어 있으면 Ansible은 인벤토리나
자체 구성에 지정된 사용자를 사용합니다.

Git 리포지토리의 경우 대신 리포지토리 URL에 사용자를 넣으세요. 예: `git@github.com:org/repo.git`.

## Passphrase {#key-sshPassphrase}

유형이 **SSH 키**일 때 표시됩니다. 선택 사항입니다.

개인 키를 암호화한 암호 문구입니다. 암호 문구가 없는 키라면 비워 두세요. 암호 문구가 틀리면 이 키를
사용하는 모든 작업이 키를 불러올 때 실패합니다. Semaphore가 생성한 키에는 암호 문구가 없으며, 이 경우 이
필드의 내용은 버려집니다.

## Generate SSH Key {#key-generateSshKey}

유형이 **SSH 키**일 때 표시됩니다.

저장할 때 Semaphore가 새 키 쌍을 만듭니다. 2048비트 RSA 개인 키는 키에 보관되고, 공개 키는 저장 후 대화
상자에 한 번 표시된 다음 키를 수정할 때마다 **Public key** 아래에 표시됩니다. 공개 키를 호스트의
`~/.ssh/authorized_keys`에 추가하거나 Git 리포지토리의 배포 키로 추가하세요.

이 상자가 체크되어 있는 동안 개인 키 필드는 잠깁니다. 기존 키에서는 먼저 **재정의**를 체크하세요. 이전 키
쌍은 교체됩니다. 비밀 값을 **Env**, **File** 또는 읽기 전용 저장소에서 읽는 키는 Semaphore가 기록할 곳이
없으므로 생성할 수 없습니다.

## 개인 키 {#key-sshPrivateKey}

유형이 **SSH 키**일 때 표시됩니다. **Generate SSH Key**가 체크되어 있지 않으면 필수입니다.

OpenSSH 또는 PEM 형식의 개인 키로, `BEGIN` 줄과 `END` 줄을 포함합니다. 작업을 실행할 때 Semaphore는 이
키를 자체 SSH 에이전트에 불러오며, Ansible과 Git은 작업이 진행되는 동안 이 에이전트를 사용합니다.

## Public key {#key-publicKey}

Semaphore가 생성한 SSH 키를 수정할 때, **재정의**가 체크되어 있지 않은 동안 표시됩니다.

생성된 키 쌍의 공개 키 부분입니다. **Show**를 누르면 펼쳐지고, 복사 버튼을 누르면 클립보드에 복사됩니다.
호스트의 `~/.ssh/authorized_keys`에 추가하거나 Git 리포지토리의 배포 키로 추가하세요.

이것은 Semaphore가 마지막으로 생성한 키 쌍의 공개 키입니다. **재정의**로 개인 키를 직접 교체한 후에는 여기에
표시되는 키가 더 이상 개인 키와 맞지 않습니다.

## 재정의 {#key-overrideSecret}

기존 키를 수정할 때 표시됩니다.

Semaphore는 저장된 비밀 값을 다시 보여 주지 않으므로, 비밀 값 필드는 비어 있고 잠겨 있습니다. 비밀 값을
교체하려면 이 상자를 체크하세요. 소스, 유형, 비밀 값 필드가 열리고 그 안의 모든 내용이 새로 저장되므로,
바뀌는 부분만이 아니라 비밀 값 전체를 다시 입력하세요. 체크하지 않으면 저장 시 키 이름만 변경됩니다.

키를 저장하면 Semaphore 서버가 그 키를 사용하는 리포지토리에 대해 보관하던 사본도 제거됩니다. 다음 작업이
리포지토리를 다시 복제합니다.
