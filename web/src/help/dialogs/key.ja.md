# 編集 Key

キーのストアのキーは、プロジェクトが表示せずに使う資格情報を保持します。Ansible がホストへのログインに使う SSH キーやパスワード、Git リポジトリの資格情報、Ansible Vault のパスワード、統合のシークレットです。インベントリ、リポジトリ、タスクテンプレート、統合は、キーを名前で参照します。保存した後、シークレットがブラウザーに送り返されることはありません。

## キー名 {#key-name}

キーのストア、およびインベントリ、リポジトリ、タスクテンプレート、統合のキー選択欄に表示されるキーの名前です。このフィールドは必須です。キーが何を開くのかがわかる名前を付けてください。例: `Deploy key of the web servers`。

## ソース {#key-source}

キーのシークレットを保管する場所です。タブは次のとおりです。

- **Local**: シークレットをこのダイアログに入力し、Semaphore のデータベースに保存します。管理者がアクセスキー用の暗号化キーを設定している場合は暗号化されます。これがデフォルトです。
- **Storage**: シークレットはプロジェクトの外部シークレットストレージに保管され、下の **Storage** で選択します。このタブは Pro エディションにのみあります。ストレージ自体は、キーのストアの **Storages** タブで設定します。
- **Env**: シークレットは Semaphore サーバーのプロセスの環境変数から読み込まれます。タブの下のフィールドに変数の名前を入力します。
- **File**: シークレットは Semaphore サーバー上のファイルから読み込まれます。タブの下のフィールドにファイルの絶対パスを入力します。ファイルはサーバーのシークレットディレクトリ (設定の `dirs.secrets`、デフォルトは `/tmp/semaphore`) の中にある必要があります。その外にあるパスや `..` を含むパスは、キーを使うときに失敗します。ファイルの末尾の改行は削除されます。

**Env** と **File** では、Semaphore はシークレットを書き込みません。タスクがキーを使うたびに値を読み込むため、シークレットはそれが保管されている場所で変更します。値はキーの **タイプ** に合っている必要があります。**文字列** のキーは値をそのまま使います。**SSHキー** または **パスワードでログイン** のキーは、そのタイプのフィールドを持つ JSON を想定します。例:

```json
{"login": "deploy", "password": "s3cret"}
```

```json
{"login": "deploy", "passphrase": "", "private_key": "-----BEGIN OPENSSH PRIVATE KEY-----\n..."}
```

キーを編集するとき、**上書き** にチェックを入れるまでタブはロックされています。シークレットストレージから同期されたキーはソースを保持し、その名前とタイプは変更できません。

## Storage {#key-sourceStorageId}

**Storage** タブを選択した場合に表示されます。

シークレットを保持するプロジェクトのシークレットストレージです。キーのストアの **Storages** タブで設定した HashiCorp Vault、OpenBao、Devolutions Server、AWS Secrets Manager、Azure Key Vault のいずれかです。

- 読み取り専用でないストレージは、このダイアログに入力したシークレットを受け取ります。保存時に Semaphore がそこに書き込みます。キーを削除すると、シークレットもストレージから削除されます。このようなストレージに保管されたキーは、後で別のストレージに移すことはできません。
- 読み取り専用のストレージは読み取られるだけです。その場合、ダイアログにはシークレットのフィールドが表示されず、Semaphore はタスクがキーを使うたびにストレージから読み込みます。

## Source Key {#key-sourceStorageKey}

**Storage** が選択されている場合に表示されます。

そのストレージ内でのシークレットの場所です。例: HashiCorp Vault 内のシークレットへのパス。

## タイプ {#key-type}

キーが保持する資格情報の種類です。このフィールドは必須で、その下のフィールドはタイプによって変わります。

- **SSHキー**: 秘密鍵と、任意のログインとパスフレーズです。Ansible はこれを使ってホストに接続し、Git は `ssh` の URL のリポジトリをこれを使ってクローンします。
- **パスワードでログイン**: ログインとパスワードです。Ansible はこれらを使ってホストに接続するか、別のユーザーに切り替えます (インベントリの **Sudo資格情報**)。Git は `https` のリポジトリをこれらを使ってクローンします。パスワードはタスクテンプレートの Ansible Vault を開きます。
- **文字列**: ログインを伴わない単一の秘密の値です。トークン、API キー、パスワードなどです。統合のシークレットに使います。SSH キー、sudo の資格情報、Vault のパスワード、リポジトリのアクセスキーとしては使えません。
- **なし**: 資格情報なしです。ログインが不要なリポジトリ (公開の `https` のリポジトリ、`file` の URL、ローカルのパス) や、ホストに資格情報が不要な、または接続方法を自ら定義するインベントリに使います。

## ユーザー名 {#key-loginPasswordLogin}

タイプが **パスワードでログイン** の場合に表示されます。任意です。

資格情報のユーザー名です。

- Ansible はこのユーザーとしてホストに接続します (`--user`)。インベントリの **Sudo資格情報** としては、Ansible が切り替える先のユーザーです (`--become-user`)。このフィールドが空の場合、Ansible はインベントリまたは自身の設定で指定されたユーザーを使います。
- `https` のリポジトリでは、Git はこのユーザーとパスワードでログインします。Git サーバーがトークンだけを受け付ける場合は空のままにします。その場合、パスワードがユーザー名として送信されます。

## パスワード {#key-loginPasswordPassword}

タイプが **パスワードでログイン** の場合に表示されます。必須です。

資格情報のパスワードです。Semaphore はこれを使って Ansible のパスワードのプロンプトに応答します。ユーザー資格情報では SSH のパスワード (`--ask-pass`)、sudo の資格情報では `become` のパスワード (`--ask-become-pass`)、Ansible Vault では Vault のパスワードです。`https` のリポジトリでは、Git サーバーのパスワードまたはアクセストークンです。

## 値 {#key-stringValue}

タイプが **文字列** の場合に表示されます。必須です。

秘密の値そのものです。例: 統合が受信したリクエストの確認に使うトークン。入力したとおりに保存されます。

## ユーザー名 {#key-sshLogin}

タイプが **SSHキー** の場合に表示されます。任意です。

Ansible がホストに接続するときのユーザーです (`--user`)。このフィールドが空の場合、Ansible はインベントリまたは自身の設定で指定されたユーザーを使います。

Git リポジトリの場合は、代わりに `git@github.com:org/repo.git` のようにユーザーをリポジトリの URL に含めます。

## Passphrase {#key-sshPassphrase}

タイプが **SSHキー** の場合に表示されます。任意です。

秘密鍵の暗号化に使われたパスフレーズです。パスフレーズのないキーの場合は空のままにします。パスフレーズが間違っていると、キーを使うすべてのタスクがキーの読み込み時に失敗します。Semaphore が生成したキーにはパスフレーズがないため、その場合このフィールドの内容は破棄されます。

## Generate SSH Key {#key-generateSshKey}

タイプが **SSHキー** の場合に表示されます。

保存時に Semaphore が新しいキーペアを作成します。2048 ビットの RSA 秘密鍵はキーに保持され、その公開鍵は保存後にダイアログで一度表示され、以後はキーを編集するたびに **Public key** の下に表示されます。公開鍵をホストの `~/.ssh/authorized_keys` に追加するか、Git リポジトリのデプロイキーとして追加してください。

チェックが入っている間、秘密鍵のフィールドはロックされます。既存のキーでは、先に **上書き** にチェックを入れてください。古いキーペアは置き換えられます。シークレットを **Env**、**File**、または読み取り専用のストレージから読み込むキーは、Semaphore に書き込み先がないため生成できません。

## 秘密鍵 {#key-sshPrivateKey}

タイプが **SSHキー** の場合に表示されます。**Generate SSH Key** にチェックが入っていない限り必須です。

OpenSSH 形式または PEM 形式の秘密鍵で、`BEGIN` 行と `END` 行を含みます。タスクのために、Semaphore はこれを独自の SSH エージェントに読み込み、Ansible と Git はタスクの間それを使います。

## Public key {#key-publicKey}

Semaphore が生成した SSH キーを編集するときに、**上書き** にチェックが入っていない間に表示されます。

生成されたキーペアの公開側の半分です。**Show** で展開し、コピーボタンでクリップボードにコピーします。ホストの `~/.ssh/authorized_keys` に追加するか、Git リポジトリのデプロイキーとして追加してください。

これは Semaphore が最後に生成したペアの公開鍵です。**上書き** で秘密鍵を手動で置き換えた後は、ここに表示される鍵はそれと一致しなくなります。

## 上書き {#key-overrideSecret}

既存のキーを編集する場合に表示されます。

Semaphore は保存したシークレットを二度と表示しないため、シークレットのフィールドは空でロックされています。シークレットを置き換えるにはチェックを入れます。ソース、タイプ、シークレットのフィールドが開き、その内容はすべて新たに保存されるため、変更する部分だけでなくシークレット全体を再度入力してください。チェックを入れない場合、保存で変更されるのはキーの名前だけです。

キーを保存すると、Semaphore サーバーがそのキーを使うリポジトリについて保持しているコピーも削除されます。次のタスクで再度クローンされます。
