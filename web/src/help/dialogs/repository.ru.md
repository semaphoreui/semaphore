# Редактировать Repository

Репозиторий — это место, откуда берутся плейбуки, код Terraform или скрипты шаблона задачи:
Git-репозиторий или каталог на машине, которая выполняет задачи. Перед каждой задачей Semaphore
клонирует Git-репозиторий или обновляет склонированную ранее копию, переключается на ветку и
выполняет задачу в этой копии.

## Имя {#repository-name}

Имя, под которым репозиторий показан на странице «Репозитории» и в списке выбора репозитория в
шаблоне задачи и в инвентаре. Поле обязательное.

## URL или путь {#repository-gitUrl}

Где находится код. Поле обязательное. Метки под полем показывают вид введенного адреса, а нажатие
на метку переписывает адрес в этот вид.

- **ssh**: `git@github.com:org/repo.git` или `ssh://git@github.com/org/repo.git`. Git входит с
  пользователем из адреса и ключом типа **SSH ключ**, выбранным в поле **Ключ доступа**.
- **https** и **http**: `https://github.com/org/repo.git`. Приватному репозиторию нужен ключ
  **Логин с паролем**; публичному — **Нет**. Избегайте `http`: логин и пароль тогда передаются
  без шифрования.
- **git**: `git://host/org/repo.git`, протокол Git только для чтения, без входа.
- **file**: `file:///srv/git/repo.git`, Git-репозиторий на диске машины, которая выполняет задачу;
  клонируется как удаленный.
- **абс. путь**: абсолютный путь, например `/srv/playbooks` или `D:\playbooks`. Semaphore не
  клонирует его: задача выполняется прямо в этом каталоге, который должен существовать на машине,
  выполняющей задачу (на сервере Semaphore или на исполнителе). Ветка к нему не применяется.

При изменении адреса удаляются копии, которые сервер Semaphore склонировал со старого адреса.

## Ветка {#repository-gitBranch}

Ветка, которую Semaphore клонирует и поддерживает в актуальном состоянии, например `main`. Поле
обязательное, кроме абсолютного пути, для которого оно заблокировано.

Шаблон задачи может указать собственную ветку, которая имеет приоритет над этой, а шаблон может
позволить своим задачам выбирать ветку при запуске. Тег тоже подходит, но тег нельзя обновить
через pull, поэтому Semaphore клонирует репозиторий заново перед каждой задачей.

## Single checkout for all templates {#repository-monorepo}

По умолчанию выключено: каждый шаблон задачи получает собственную копию репозитория. Установите
флажок, чтобы склонировать репозиторий один раз и использовать эту копию во всех шаблонах, которые
его используют, — для репозитория, слишком большого, чтобы хранить по копии на каждый шаблон.

Общая копия остается на ветке этого репозитория: у шаблонов, которые ее используют, не может быть
собственной ветки, а их задачи не могут выбрать другую ветку или коммит. Заблокировано для
абсолютного пути.

## Ключ доступа {#repository-sshKeyId}

Ключ из раздела «Хранилище ключей», с которым Git входит в репозиторий. Поле обязательное. В нем
предлагаются ключи трех типов; какой выбрать, зависит от URL:

- **SSH ключ** для URL `ssh`. Semaphore загружает закрытый ключ в SSH-агент на время клонирования
  или обновления. Пользователь — тот, что указан в URL, например `git` в
  `git@github.com:org/repo.git`.
- **Логин с паролем** для URL `https`: логин и пароль или токен доступа Git-сервера. С пустым
  логином пароль отправляется сам по себе, как имя пользователя, — именно этого некоторые серверы
  ожидают от токена. Те же учетные данные передаются `ansible-galaxy` для ролей и коллекций на том
  же сервере.
- **Нет** для публичного репозитория, URL `git` или `file` или абсолютного пути.

Ключ, который не подходит к URL, не дает Git учетных данных, и тогда приватный репозиторий не
удается склонировать.
