# Сховище

Сховище передає Ansible пароль до файлів і змінних, зашифрованих за допомогою Ansible Vault у
репозиторії з playbook. Кожне сховище шаблону стає однією опцією `--vault-id` для
`ansible-playbook`. Сховище зберігається разом із шаблоном, коли ви зберігаєте діалог шаблону.

## Vault ID {#templateVaultDialog-name}

Необов’язкове поле. Vault ID, для якого призначено пароль, — мітка, з якою зашифровано вміст
(`ansible-vault encrypt --vault-id prod@prompt`). Залиште поле порожнім для vault ID `default`.

ID зберігається в нижньому регістрі. Кожному сховищу шаблону потрібен власний ID, і лише один може
бути порожнім.

## Тип {#templateVaultDialog-type}

Звідки береться пароль:

- **Пароль**: ключ зі «Сховища ключів». Semaphore вводить його пароль, коли Ansible його
  запитує, тож пароль ніколи не записується у файл.
- **Клієнтський скрипт**: клієнтський скрипт пароля vault, який виводить пароль; Ansible його
  запускає.

## Пароль сховища {#templateVaultDialog-vaultKeyId}

Відображається, коли вибрано тип **Пароль**.

Ключ, який містить пароль vault. У списку є лише ключі типу **Логін з паролем**; Semaphore
використовує їхній пароль і ігнорує логін. Поле обов’язкове.

## Шлях до скрипта {#templateVaultDialog-script}

Відображається, коли вибрано тип **Клієнтський скрипт**.

Шлях до скрипта, наприклад `scripts/vault-pass-client.py`. Відносний шлях відраховується від
каталогу, в якому запускається Ansible: кореня репозиторію або робочого каталогу шаблону, якщо
його задано. Поле обов’язкове.

Назва файлу має закінчуватися на `-client`, з розширенням або без: лише тоді Ansible запускає
файл як клієнтський скрипт і передає йому vault ID через `--vault-id`. Скрипт виконується на
машині, яка виконує завдання, від імені користувача, від якого працює Semaphore.
