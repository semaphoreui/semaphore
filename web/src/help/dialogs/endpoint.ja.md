# エンドポイントを編集

エンドポイントは webhook の入口です。他のサービスが呼び出す URL
と、そのリクエストを検証する方法を持ちます。インテグレーションはエンドポイントに接続し、エンドポイントが受け付けたリクエストで実行を開始します。エンドポイントの
URL（エイリアス）は「エンドポイント」タブで追加します。

## 名前 {#endpointForm-name}

「エンドポイント」タブとインテグレーションのフォームに表示されるエンドポイントの名前です。このフィールドは必須です。

## 説明 {#endpointForm-description}

任意です。エンドポイントの用途についてのメモで、名前の横に表示されます。

## 認証方式 {#integrationAuthForm-authMethod}

リクエストが想定したサービスから来たことを Semaphore が確認する方法です。確認に失敗したリクエストは何も開始せず、Webhook は他のリクエストと同じように応答します。

- **なし**: 確認しません。URL を知っている人なら誰でもタスクを開始できます。
- **GitHub Webhooks**: `X-Hub-Signature-256` ヘッダーに、GitHub が送るとおり、シークレットで作成したボディの HMAC-SHA256 署名が含まれている必要があります。
- **Bitbucket Webhooks**: Bitbucket が送るとおり、`X-Hub-Signature` ヘッダーに対して同じ確認を行います。
- **Token**: **認証ヘッダー** に指定したヘッダーに、シークレットそのものが含まれている必要があります。
- **HMAC** と **HMAC (SHA-512)**: **認証ヘッダー** に指定したヘッダーに、シークレットで作成したボディの HMAC-SHA256 または HMAC-SHA512 が、小文字の 16 進数で、`sha256=` のような接頭辞なしで含まれている必要があります。
- **BasicAuth**: リクエストの `Authorization` ヘッダーに、**認証シークレット** のキーのログインとパスワードが含まれている必要があります。

## 認証ヘッダー {#integrationAuthForm-authHeader}

**認証方式** が **Token**、**HMAC**、**HMAC (SHA-512)** の場合に表示されます。

トークンまたは署名を運ぶリクエストヘッダーの名前です。例: `X-Webhook-Token`。名前の大文字と小文字は区別されません。そのヘッダーのないリクエストは拒否されます。

## 認証シークレット {#integrationAuthForm-authSecretId}

**認証方式** が **なし** 以外の場合に表示されます。

リクエストの確認に使われる、キーのストアのキーです。**BasicAuth** には **パスワードでログイン** タイプのキーのみが使えます。その他の方法には **文字列** タイプのキーも使えます。確認にはその値、または **パスワードでログイン** のキーのパスワードが使われます。

このフィールドは **なし** 以外のすべての方法で必要です。キーがない場合、またはシークレットが空の場合、すべてのリクエストが拒否されます。
