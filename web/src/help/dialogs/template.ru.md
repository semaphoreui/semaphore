# Редактировать шаблон 'Ansible Playbook'

Шаблон задачи определяет, что и как выполняет Semaphore: репозиторий и файл в нем, инвентарь и
переменные, а также какие параметры пользователь может изменить при запуске задачи. Каждая задача
запускается из шаблона. Поля диалога зависят от приложения шаблона (Ansible, Terraform, OpenTofu,
Terragrunt, Bash, Python, PowerShell и другие): если поле есть только у некоторых приложений, об
этом сказано. Изменения действуют для задач, запущенных после нажатия **Сохранить**.

## Тип шаблона {#templateForm-typeTabs}

Вкладки вверху задают вид шаблона:

- **Задача**: выполняет код. Большинство шаблонов — этого вида.
- **Сборка**: создает артефакт. Каждая задача сборки получает версию, отсчитываемую от
  **Начальная версия**.
- **Развертывание**: развертывает артефакт, созданный сборкой. При запуске вы выбираете задачу
  сборки, версию которой она развертывает.

Задача сборки или развертывания получает в своем окружении переменные `SEMAPHORE_TASK_TYPE`,
`SEMAPHORE_TASK_TARGET_VERSION` (сборка) и `SEMAPHORE_TASK_INCOMING_VERSION` (развертывание).
Ansible получает те же значения в дополнительной переменной `semaphore_vars.task_details`.

## Начальная версия {#templateForm-startVersion}

Показывается, когда выбран тип **Сборка**. Обязательное поле.

Версия первой задачи сборки, например `1.0.0` или `v0.1`. Каждая следующая сборка увеличивает
последнее число предыдущей версии на единицу и сохраняет окружающий его текст и ведущие нули:
`1.0.0`, `1.0.1`, `1.0.2`. Укажите здесь число больше последней сборки, чтобы перескочить вперед,
например на `2.0.0`; версия без числа никогда не меняется.

## Шаблон сборки {#templateForm-buildTemplateId}

Показывается, когда выбран тип **Развертывание**. Обязательное поле.

Шаблон, задачи которого создают артефакты, развертываемые этим шаблоном. В списке перечислены
шаблоны сборки проекта, а под ними — шаблоны развертывания: развертывание может следовать за
другим развертыванием и тогда получает версию, которую то получило от своей сборки.

## Автозапуск {#templateForm-autorun}

Показывается, когда выбран тип **Развертывание**.

Автоматически запускает задачу этого шаблона каждый раз, когда задача из поля **Шаблон сборки**
завершается успешно, с версией, которую создала эта задача. Неудачная сборка ничего не запускает.

## Имя {#templateForm-name}

Имя, под которым шаблон показан на странице «Шаблоны задач». Поле обязательное.

## Репозиторий {#templateForm-repositoryId}

Репозиторий проекта, в котором находится выполняемый код. Поле обязательное. Перед каждой задачей
Semaphore обновляет свою копию репозитория и выполняет код из нее.

Метка справа от поля показывает ветку, которую извлекают задачи. Нажмите на нее, чтобы открыть
поле **Ветка**.

## Ветка {#templateForm-gitBranch}

Показывается после нажатия на метку ветки справа от поля **Репозиторий**.

Ветка или тег, которые извлекают задачи этого шаблона вместо ветки, заданной в репозитории.
Оставьте поле пустым, чтобы использовать ветку репозитория. Если Semaphore может прочитать ветки
репозитория, поле предлагает их список.

Поле недоступно, если репозиторий является монорепозиторием: все шаблоны используют одну его
копию на ветке репозитория.

## Путь к файлу плейбука {#templateForm-playbook}

Что выполнять, в виде пути от корня репозитория, например `deploy/site.yml`. Путь не может быть
абсолютным и не может выходить за пределы репозитория. Список предлагает файлы репозитория; можно
также ввести путь, которого нет в списке. Кнопка справа от поля заново считывает список.

Подпись и смысл поля меняются вместе с приложением:

- **Ansible**: плейбук. Поле обязательное; список предлагает файлы `.yml` и `.yaml`.
- **Terraform**, **OpenTofu**, **Terragrunt**: **Subdirectory path** — каталог с кодом. Оставьте
  поле пустым, чтобы выполнять код в корне репозитория. Введите `/`, чтобы увидеть содержимое
  каталога.
- **Bash**, **Python**, **PowerShell** и другие приложения: **Script Filename** — выполняемый
  скрипт. Поле обязательное. Скрипт выполняется в корне репозитория.

## Different working directory {#templateForm-workingDirectoryToggle}

Показывается для шаблонов Ansible.

Запускает `ansible-playbook` в каталоге, отличном от корня репозитория. Установите флажок, чтобы
показать поле **Working directory**. Снимите его, чтобы снова выполнять в корне.

## Working directory {#templateForm-workingDirectory}

Показывается, когда установлен флажок **Different working directory**. Обязательное поле.

Каталог, в котором запускаются `ansible-playbook` и `ansible-galaxy`, в виде пути от корня
репозитория, например `ansible`. Используйте его, когда `ansible.cfg` проекта находится в
подкаталоге, так как Ansible читает этот файл из текущего каталога. Путь к плейбуку по-прежнему
отсчитывается от корня репозитория. Путь не может быть абсолютным и не может выходить за пределы
репозитория.

## Инвентарь {#templateForm-inventoryId}

Показывается для шаблонов Ansible, Terraform, OpenTofu и Terragrunt.

- **Ansible**: инвентарь, с которым выполняется плейбук, вместе с учетными данными для хостов.
  Поле обязательное.
- **Terraform**, **OpenTofu**, **Terragrunt**: **Workspace** — workspace, в котором выполняется
  код. Semaphore выбирает его перед планом и создает, если его нет. Новый шаблон, сохраненный без
  workspace, получает workspace с именем `default`.

В списке перечислены инвентари проекта, созданные для приложения шаблона.

## Группы переменных {#templateForm-environmentIds}

Необязательное поле. Группы переменных, переменные, переменные окружения и секреты которых
получает каждая задача этого шаблона. Можно выбрать несколько: они объединяются в порядке поля, и
более поздняя группа имеет приоритет над более ранней, если обе задают одно и то же имя.

Как переменные доходят до кода, зависит от приложения: дополнительные переменные для Ansible,
`-var` для Terraform и OpenTofu, аргументы `name=value` для скрипта. Переменные окружения
задаются для любого приложения.

## Представление {#templateForm-viewId}

Необязательное поле. Представление, в котором показан шаблон: представления — это вкладки
страницы «Шаблоны задач», которые группируют шаблоны проекта. Оставьте поле пустым, чтобы не
помещать шаблон ни в одно представление.

## Тег исполнителя {#templateForm-runnerTag}

Показывается, когда доступны исполнители проекта.

Задачи этого шаблона выполняются только на исполнителе с этим тегом, даже если сервер мог бы
выполнить их сам. Тег переопределяет тег исполнителя инвентаря. Оставьте поле пустым, чтобы
использовать тег инвентаря или обойтись без тега.

## Executor image {#templateForm-executorImage}

Образ контейнера, который исполнитель запускает для задач этого шаблона, например
`semaphoreui/job:latest`. Оставьте поле пустым, чтобы использовать образ из конфигурации
исполнителя.

Задачи в контейнере выполняют только исполнители Docker и Kubernetes, поэтому поле доступно,
только когда один из них есть. Задача, которая выполняется без контейнера, его игнорирует.

## Переменные опроса {#surveyVars}

Значения, которые у пользователя запрашиваются при запуске задачи этого шаблона. Нажмите **+**,
чтобы добавить переменную, на метку — чтобы изменить ее, на крестик на метке — чтобы удалить ее;
перетаскивайте метки, чтобы задать порядок вопросов.

Ответы доходят до кода как переменные группы переменных или как переменные окружения — как задано
в каждой переменной. Они имеют приоритет над группой переменных, которая задает то же имя.

## Allow parallel tasks {#templateForm-allowParallelTasks}

Позволяет задачам этого шаблона выполняться одновременно. Без этого флажка задача шаблона ждет в
очереди, пока не завершится выполняемая. Лимиты параллельных задач проекта и сервера действуют в
любом случае.

## Issue JWT to task runner {#templateForm-jwtEnabled}

Показывается, когда администратор включил выдачу JWT для сервера.

Выдает каждой задаче этого шаблона JSON Web Token, подписанный Semaphore, в переменной окружения
`SEMAPHORE_JWT`. Код может предъявить токен другому сервису, чтобы доказать, какая это задача:
токен называет задачу, проект, шаблон и пользователя, который ее запустил. Сервис проверяет
подпись по открытым ключам по адресу `/.well-known/jwks.json` сервера Semaphore.

## JWT audience {#templateForm-jwtAudience}

Показывается, когда установлен флажок **Issue JWT to task runner**. Необязательное поле.

Сервисы, для которых предназначен токен; записываются в его claim `aud`, например
`https://vault.example.com`. Нажимайте Enter после каждого значения. До 32 значений; оставьте
поле пустым для токена без audience.

## JWT TTL {#templateForm-jwtTtl}

Показывается, когда установлен флажок **Issue JWT to task runner**. Необязательное поле.

Сколько токен остается действительным с начала задачи, в виде длительности, например `30s`, `15m`
или `1h`. Оставьте поле пустым, чтобы использовать значение сервера по умолчанию — один час, если
администратор не задал другое. Значение не может превышать максимум сервера — 24 часа, если не
задано иное.

## Я хочу запускать задачу по cron только для новых коммитов некоторого репозитория {#templateForm-cronVisible}

Запускает задачу этого шаблона, когда в репозитории появляется новый коммит. Semaphore с
выбранным интервалом запрашивает у репозитория его последний коммит и запускает задачу, только
если коммит изменился с последней проверки.

Если установить флажок и сохранить, создается расписание проверки; если снять его и сохранить,
это расписание удаляется. Остальные расписания шаблона сохраняются.

## Репозиторий {#templateForm-cronRepositoryId}

Показывается, когда установлен флажок **Я хочу запускать задачу по cron только для новых
коммитов некоторого репозитория**. Обязательное поле.

Репозиторий, в котором отслеживаются новые коммиты. Semaphore отслеживает ветку, заданную в этом
репозитории, а не **Ветка** шаблона.

## интервалПроверки {#templateForm-cronFormat}

Показывается, когда установлен флажок **Я хочу запускать задачу по cron только для новых
коммитов некоторого репозитория**.

Как часто Semaphore проверяет репозиторий на новый коммит: от каждой минуты до раза в день. По
умолчанию — каждую минуту.

## Подавить успешные оповещения {#templateForm-suppressSuccessAlerts}

Не дает успешно завершившимся задачам этого шаблона отправлять оповещения. Оповещения о неудачных
задачах по-прежнему отправляются. Действует, только если оповещения включены для проекта.

## Подавить оповещения об ошибках {#templateForm-suppressErrorAlerts}

Не дает задачам этого шаблона, завершившимся с ошибкой, отправлять оповещения. Оповещения об
успешных задачах по-прежнему отправляются. Действует, только если оповещения включены для
проекта.

## CLI args {#templateForm-args}

Аргументы, добавляемые к команде каждой задачи. Каждый элемент — один аргумент, передаваемый как
есть, без оболочки: укажите `--forks=10` в одном элементе или `--forks` и `10` в двух.
Перетаскивайте элементы, чтобы изменить их порядок. Кнопка справа от списка открывает аргументы в
виде массива JSON:

```json
["--forks=10", "-e", "env=staging"]
```

- **Ansible**: добавляются к `ansible-playbook` перед плейбуком.
- **Terraform**, **OpenTofu**, **Terragrunt**: добавляются к `plan` и `apply`, но не к `init`.
- Скрипт: добавляются после имени скрипта.

## CLI аргументы {#templateForm-allowOverrideArgsInTask}

В разделе **Подсказки**. Позволяет пользователю добавлять собственные аргументы при запуске
задачи. Они добавляются после аргументов шаблона.

## Ветка {#templateForm-allowOverrideBranchInTask}

В разделе **Подсказки**. Позволяет пользователю выбрать другую ветку, тег или коммит при запуске
задачи вместо ветки шаблона. Без этого флажка задача всегда извлекает ветку шаблона.

Флажок недоступен, если репозиторий является монорепозиторием.

## Инвентарь {#templateForm-allowOverrideInventory}

В разделе **Подсказки**. Показывается для шаблонов Ansible, Terraform, OpenTofu и Terragrunt.

Позволяет пользователю выбрать другой инвентарь при запуске задачи. Выбранный там инвентарь
используют только шаблоны Ansible: задача Terraform, OpenTofu или Terragrunt выполняется в
workspace шаблона, даже если флажок установлен.

## Лимит {#templateForm-limit}

Показывается для шаблонов Ansible.

Хосты или группы инвентаря, на которых выполняется плейбук; передаются как `--limit`. Каждый
элемент — один шаблон, например `web` или `db01`; оставьте список пустым, чтобы выполнять на всех
хостах.

## Теги {#templateForm-tags}

Показывается для шаблонов Ansible.

Выполняет только задачи и роли с этими тегами; передаются как `--tags`. Оставьте список пустым,
чтобы выполнять все.

## Пропустить теги {#templateForm-skipTags}

Показывается для шаблонов Ansible.

Пропускает задачи и роли с этими тегами; передаются как `--skip-tags`.

## Хранилища {#templateVaults}

Показывается для шаблонов Ansible.

Пароли Ansible Vault, которые нужны плейбуку для расшифровки его файлов. Нажмите **+**, чтобы
добавить пароль, на метку — чтобы изменить его, на крестик на метке — чтобы удалить его. У
каждого хранилища есть имя — его vault ID, — и оно передает пароль из ключа раздела «Хранилище
ключей» или из клиентского скрипта репозитория.

## Авто одобрение {#templateForm-autoApprove}

Показывается для шаблонов Terraform, OpenTofu и Terragrunt.

Применяет план без вопросов. Без этого флажка задача останавливается после плана и ждет, пока
пользователь не подтвердит или не отклонит ее; план без изменений завершает задачу, так как
применять нечего.

## Override backend settings {#templateForm-overrideBackend}

Показывается для шаблонов Terraform, OpenTofu и Terragrunt, когда Semaphore может хранить
состояние Terraform.

Хранит состояние кода в Semaphore. Перед `init` Semaphore записывает в каталог кода файл, который
задает backend `http`, и удаляет его после задачи:

```hcl
terraform {
  backend "http" {
  }
}
```

## Backend filename {#templateForm-backendFilename}

Показывается вместе с **Override backend settings**; доступно, когда этот флажок установлен.
Необязательное поле.

Имя файла, в который Semaphore записывает backend, например `semaphore_backend.tf`. По умолчанию
`backend.tf`. Имя должно заканчиваться на `.tf` и содержать только буквы, цифры, `_`, `-` и `.`.
Выберите имя, которого нет ни у одного файла вашего кода: Semaphore перезаписывает этот файл и
удаляет его после задачи.

## Лимит {#templateForm-allowOverrideLimit}

В разделе **Ansible подсказки**. Позволяет пользователю задать хосты для выполнения при запуске
задачи вместо **Лимит** шаблона.

## Теги {#templateForm-allowOverrideTags}

В разделе **Ansible подсказки**. Позволяет пользователю задать теги при запуске задачи вместо
**Теги** шаблона.

## Пропустить теги {#templateForm-allowOverrideSkipTags}

В разделе **Ansible подсказки**. Позволяет пользователю задать пропускаемые теги при запуске
задачи вместо **Пропустить теги** шаблона.

## Отладка {#templateForm-allowDebug}

В разделе **Ansible подсказки**. Позволяет пользователю включить подробный вывод при запуске
задачи, от `-v` до `-vvvvvv`.

## Пробный запуск {#templateForm-showDryRun}

В разделе **Ansible подсказки**. По умолчанию флажок установлен. Предлагает параметр **Пробный
запуск** при запуске задачи, который запускает плейбук с `--check`: Ansible сообщает, что он
изменил бы, и ничего не меняет. Снимите флажок, чтобы убрать этот параметр.

## Различия {#templateForm-showDiff}

В разделе **Ansible подсказки**. По умолчанию флажок установлен. Предлагает параметр
**Различия** при запуске задачи, который запускает плейбук с `--diff`, чтобы показать изменения,
внесенные в файлы. Снимите флажок, чтобы убрать этот параметр.

## Авто одобрение {#templateForm-allowAutoApprove}

В разделе подсказок Terraform, OpenTofu и Terragrunt. Позволяет пользователю установить флажок
**Auto Approve** при запуске задачи, чтобы применить план без подтверждения. Диалог задачи
предлагает этот параметр в любом случае, но без этого флажка Semaphore его игнорирует: задача
ждет подтверждения после плана, если только не установлен флажок **Авто одобрение** шаблона.

## Galaxy install options {#templateForm-galaxy}

Показывается для шаблонов Ansible. Нажмите на этот блок, чтобы показать параметры установки
Galaxy; метка показывает количество параметров, отличающихся от значений по умолчанию.

Перед запуском плейбука Semaphore устанавливает с помощью `ansible-galaxy` роли и коллекции,
которые запрашивает репозиторий. Он ищет `requirements.yml`, `roles/requirements.yml` и
`collections/requirements.yml` рядом с плейбуком и в корне репозитория и выполняет установку,
только если файл изменился с последней задачи.

## Пропустить установку Galaxy {#templateForm-skipGalaxyInstall}

В разделе **Galaxy install options**. Пропускает установку Galaxy: плейбук выполняется с ролями и
коллекциями, установленными ранее. Используйте это, когда зависимости устанавливаются другим
способом или установка медленная и не нужна.

## Role install args {#templateForm-galaxyRoleArgs}

В разделе **Galaxy install options**. Аргументы, добавляемые к `ansible-galaxy role install`, по
одному на элемент, например `--ignore-certs` или `--server=https://galaxy.example.com`. Semaphore
принимает только те флаги установки, которые безопасно передавать: из-за неизвестного флага,
`--token`, `--api-key`, `-p` или `--roles-path` шаблон не удается сохранить.

## Collection install args {#templateForm-galaxyCollectionArgs}

В разделе **Galaxy install options**. Аргументы, добавляемые к
`ansible-galaxy collection install`, по одному на элемент, например `--pre` или `--upgrade`. Действует то же правило, что и
для **Role install args**: `--token`, `--api-key`, `-p` и `--collections-path` не принимаются.

## Пропустить установку Galaxy {#templateForm-allowOverrideSkipGalaxyInstall}

В разделе **Galaxy install options**, в блоке **Prompts**. Позволяет пользователю при запуске
задачи выбрать, пропускать ли установку Galaxy. Выбор задачи имеет приоритет над **Пропустить
установку Galaxy** шаблона.
