# Clear tasks from Redis

클러스터의 노드는 작업 풀의 상태를 Redis에서 공유합니다. 어떤 작업이 대기 중이고 어떤 작업이 실행 중인지,
각 작업을 어느 노드가 소유하는지가 여기에 해당합니다. 이 대화 상자는 체크한 레코드 그룹을 Redis에서
삭제하여, 멈춘 클러스터를 복구합니다. 예를 들어 끝난 작업이 여전히 실행 중으로 표시되는 경우입니다.
데이터베이스에서는 아무것도 삭제되지 않습니다. 작업의 상태, 로그, 기록은 그대로 유지됩니다.

무엇을 체크하든 모든 노드는 메모리에 보관하던 작업도 버리고 Redis와 데이터베이스에서 다시 읽습니다.
대화 상자가 열릴 때는 **Queue**만 체크되어 있습니다. 멈춘 그룹만 체크하세요. 결과에는 제거된 레코드 수가
표시됩니다.

## Queue {#clusterClearDialog-queue}

노드가 시작하기를 기다리는 작업입니다. 지워진 작업은 시작되지 않으며, 대기 중 상태로 데이터베이스에
남습니다. 이 작업들을 중지하거나 해당 템플릿을 다시 실행하세요.

## Running {#clusterClearDialog-running}

클러스터가 실행 중으로 집계하는 작업입니다. 지워도 작업이 중지되지는 않으며, 작업은 러너에서 계속
실행됩니다. 하지만 클러스터는 그 작업을 추적하지 못하게 됩니다. 작업이 더 이상 서버와 러너의 병렬 작업
한도에 포함되지 않으므로 한도보다 많은 작업이 시작될 수 있고, 러너가 아직 가져가지 않은 작업은 더 이상
러너에 전달되지 않습니다.

## Active by project {#clusterClearDialog-active}

각 프로젝트의 끝나지 않은 작업입니다. 이 레코드는 프로젝트의 병렬 작업 한도를 적용하고, 템플릿이 병렬
작업을 허용하지 않을 때 한 작업이 실행되는 동안 같은 템플릿의 두 번째 작업이 시작되지 않게 합니다.
프로젝트의 작업이 이미 끝난 작업 뒤에서 끝없이 기다릴 때 이 그룹을 지우세요. 그 순간 실행 중인 작업은
더 이상 집계되지 않으므로, 프로젝트의 새 작업이 그 옆에서 시작될 수 있습니다.

## Aliases {#clusterClearDialog-aliases}

Terraform, OpenTofu, Terragrunt 작업이 실행되는 동안 받는 임의의 이름과 그 작업의 대응 관계입니다. 실행
중인 작업은 이 이름으로 서버에 있는 Terraform 상태에 접근합니다. 지우고 나면 이 앱들의 실행 중인 작업을
이 이름으로 더 이상 찾을 수 없습니다.

## Claims {#clusterClearDialog-claims}

각 작업을 어느 노드가 소유하는지에 대한 정보입니다. 노드는 자신의 작업에 대한 소유권을 1분마다 갱신하며,
갱신되지 않은 소유권은 5분 후에 만료됩니다. 소유권이 없는 작업은 고아 작업으로 간주됩니다. 아직 러너에
도달하지 않은 작업은 다른 노드를 위해 대기열에 다시 들어가고, 러너가 이미 실행 중인 작업은 그곳에서
끝나도록 둡니다.

## Runtime fields {#clusterClearDialog-runtimeFields}

데이터베이스에 없는 각 작업의 세부 정보입니다. 작업을 시작한 사용자, 시작할 때의 버전, 별칭, 러너, 상태,
그리고 각 작업의 프로젝트가 여기에 해당합니다. 이 정보가 없으면 작업을 시작하지 않은 노드는 그 작업에
대해 더 적은 정보를 표시하고, 고아 작업 정리기는 실행 중인 작업을 건너뛰므로 멈춘 레코드가 저절로
제거되지 않습니다.
