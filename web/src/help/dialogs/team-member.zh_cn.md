# 新建 团队成员

将用户以某个角色添加到项目中。角色决定成员在项目中可以查看和执行的内容；其账户的其他内容不会改变。
如果管理员启用了邀请，用户会收到一份邀请，并在接受邀请后成为成员。

## Email 或 Username {#teamMember-inviteType}

当既可以通过电子邮件也可以通过用户名邀请用户时显示。

选择人员的方式：**Email** 表示邀请一个电子邮件地址，**Username** 表示选择一个在此 Semaphore 服务器上已有账户的用户。

## 电子邮件 {#teamMember-email}

当通过电子邮件邀请人员时显示。

要邀请的人员的电子邮件地址。对方接受邀请后即成为项目的成员。

## 用户 {#teamMember-userId}

当通过用户名选择人员时显示。

要添加的用户，以用户名和全名列出。此字段为必填项。列表包含 Semaphore 服务器上所有尚未成为项目成员的用户：
没有账户的人员必须先由管理员为其创建账户。

## 角色 {#teamMember-role}

成员可以在项目中执行的操作。此字段为必填项。内置角色：

- **Owner**：所有操作，包括项目的设置、团队以及删除项目。
- **Manager**：运行任务和工作流、批准工作流，以及创建、更改和删除任务模板、库存、密钥、仓库、变量组、计划、集成和工作流。
  管理者不能更改项目的设置或其团队。
- **Task Runner**：查看项目、运行任务和工作流以及批准工作流。任务执行者不能更改项目中的任何内容。
- **Guest**：查看项目、其任务及任务日志，不能更改任何内容。

列表中还包含为此项目创建的角色（**项目角色**）以及所有项目共享的角色（**Shared roles**）。这样的角色授予在 Roles
页面中为其设置的权限。邀请只能携带内置角色。

能够管理团队的成员可以授予任何角色，包括 **Owner**。此对话框只授予一个角色；之后可以在团队列表的**角色**列中添加更多角色。
