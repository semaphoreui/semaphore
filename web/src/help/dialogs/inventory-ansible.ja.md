# 編集 Ansible Inventory

インベントリは、Ansible がどのホストに対してプレイブックを実行するかを示し、Semaphore がそれらのホストへの接続に使う資格情報を保持します。タスクテンプレートはインベントリを参照し、そのテンプレートのすべてのタスクはそのインベントリに対して実行されます。インベントリの形式は [Ansible インベントリガイド](https://docs.ansible.com/ansible/latest/inventory_guide/intro_inventory.html) で説明されています。

## 名前 {#inventoryForm-name}

インベントリページとタスクテンプレートのインベントリ選択欄に表示されるインベントリの名前です。ホストを区別できる名前を付けてください。例: `Production web servers`。

## ランナータグ {#inventoryForm-runnerTag}

プロジェクトのランナーが利用できる場合に表示されます。

このインベントリを使うタスクは、このタグを持つランナーで実行されます。タスクテンプレートに設定されたランナータグは、インベントリのタグよりも優先されます。どのランナーでもタスクを実行できるようにするには、このフィールドを空のままにします。

## ユーザー資格情報 {#inventoryForm-sshKeyId}

Ansible がホストへのログインに使う、キーのストアのキーです。このフィールドは必須で、次の 3 種類のキーを指定できます。

- **SSHキー**: Ansible は秘密鍵と、キーにログインが設定されている場合はそのログインを使って接続します。
- **パスワードでログイン**: Ansible はログインとパスワードを使って接続します。
- **なし**: Semaphore は資格情報を渡しません。`localhost` のように資格情報が不要なホストや、インベントリ自体が接続方法を定義している場合に使います。

## Sudo資格情報 {#inventoryForm-becomeKeyId}

任意です。キーのストアにある **パスワードでログイン** タイプのキーで、プレイが `become` によって権限を昇格するときに使われます。そのログインは Ansible が切り替える先のユーザーで、そのパスワードは Ansible がプロンプトに応答するパスワードです。

プレイが権限を昇格しない場合、または上記のユーザーが権限の昇格にパスワードを必要としない場合は、このフィールドを空のままにします。

## タイプ {#inventoryForm-type}

インベントリの取得元です。

- **Static**: インベントリを INI 形式でこのダイアログに入力します。
- **Static YAML**: インベントリを YAML 形式でこのダイアログに入力します。インベントリプラグインの設定にも使います。
- **File**: インベントリは Git リポジトリ内のファイルです。
- **Managed**: ホストとその変数をレコードとして保存します。編集するには、一覧からインベントリを開きます。

タイプに応じて、その下のフィールドが変わります。

## インベントリファイルへのパス {#inventoryForm-inventoryPath}

タイプが **File** の場合に表示されます。

リポジトリのルートからのインベントリファイルのパスです。例: `inventory/production.yml`。リポジトリは、リポジトリフィールドで選択したもの、またはそのフィールドが空の場合は、このインベントリを使うタスクテンプレートのリポジトリです。

## リポジトリ {#inventoryForm-repositoryId}

タイプが **File** の場合に表示されます。任意です。

インベントリファイルを保持するリポジトリです。Semaphore はタスクのたびに、そのリポジトリのコピーを更新します。ファイルがプレイブックと同じリポジトリにある場合は、このフィールドを空のままにします。その場合、パスはタスクテンプレートのリポジトリ内で検索されます。

## インベントリ {#inventoryForm-inventoryCode}

タイプが **Static** または **Static YAML** の場合に表示されます。

インベントリのテキストです。Semaphore はこれを保存し、タスクのたびに一時ファイルに書き出します。INI 形式の静的インベントリの例:

```ini
[web]
10.0.0.11
10.0.0.12

[db]
10.0.0.21 ansible_port=2222
```

同じホストを **Static YAML** で記述した例:

```yaml
web:
  hosts:
    10.0.0.11:
    10.0.0.12:
db:
  hosts:
    10.0.0.21:
      ansible_port: 2222
```
