# Clear tasks from Redis

クラスターのノードは、タスクプールの状態を Redis で共有しています。どのタスクが待機中で、どのタスクが実行中で、どのノードがそれぞれのタスクを所有しているかという情報です。このダイアログは、チェックを入れたレコードのグループを Redis から削除し、停止したクラスターを回復します。たとえば、終了したタスクがまだ実行中と表示される場合です。データベースからは何も削除されません。タスクのステータス、ログ、履歴は保持されます。

何にチェックを入れても、すべてのノードはメモリに保持しているタスクを破棄し、Redis とデータベースから再度読み込みます。ダイアログを開いたときにチェックが入っているのは **Queue** のみです。停止しているグループにのみチェックを入れてください。結果には、削除されたレコードの数が表示されます。

## Queue {#clusterClearDialog-queue}

ノードによる開始を待っているタスクです。クリアされたタスクは開始されません。データベースにステータス Waiting のまま残ります。それらを停止するか、テンプレートを再度実行してください。

## Running {#clusterClearDialog-running}

クラスターが実行中とみなしているタスクです。クリアしてもタスクは停止しません。タスクはランナー上で実行を続けます。ただし、クラスターはそのタスクを追跡できなくなります。タスクはサーバーとランナーの並列タスク数の上限に数えられなくなるため、上限を超えてタスクが開始されることがあります。また、ランナーがまだ受け取っていないタスクは、ランナーに渡されなくなります。

## Active by project {#clusterClearDialog-active}

各プロジェクトの未完了のタスクです。これらはプロジェクトの並列タスク数の上限を適用し、テンプレートが並列タスクを許可していない場合に、実行中のタスクがあるテンプレートの 2 つ目のタスクが開始されないようにします。プロジェクトのタスクが、終了したタスクの後ろで永久に待機する場合に、このグループをクリアします。その時点で実行中のタスクは数えられなくなるため、プロジェクトの新しいタスクがそれらと並行して開始されることがあります。

## Aliases {#clusterClearDialog-aliases}

Terraform、OpenTofu、Terragrunt のタスクが実行期間中に受け取るランダムな名前と、そのタスクとの対応です。実行中のタスクは、この名前でサーバー上の Terraform の状態にアクセスします。クリアした後は、これらのアプリの実行中のタスクをこの名前で見つけられなくなります。

## Claims {#clusterClearDialog-claims}

どのノードがどのタスクを所有しているかという情報です。ノードは自分のタスクのクレームを 1 分ごとに更新し、更新されないクレームは 5 分後に期限切れになります。クレームのないタスクは孤立したタスクとみなされます。まだランナーに届いていないタスクは、別のノードのためにキューに戻され、すでにランナーが実行しているタスクはそこで終了するまで残されます。

## Runtime fields {#clusterClearDialog-runtimeFields}

データベースが保持していない各タスクの詳細です。タスクを開始したユーザー、開始時のバージョン、エイリアス、ランナー、ステータス、および各タスクのプロジェクトです。これらがないと、タスクを開始していないノードではそのタスクについて表示される情報が少なくなります。また、孤立したタスクのクリーナーは実行中のタスクをスキップするため、停止したレコードは自動的に削除されなくなります。
