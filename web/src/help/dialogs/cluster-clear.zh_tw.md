# Clear tasks from Redis

叢集的節點在 Redis 中共享任務池的狀態：哪些任務在等候、哪些在執行，以及每個任務歸哪個節點所有。此對話方塊會從 Redis
刪除您勾選的記錄群組，用來復原卡住的叢集，例如某個已結束的任務仍顯示為執行中。資料庫中的任何內容都不會被刪除：
任務會保留其狀態、日誌和歷史。

無論您勾選什麼，每個節點也都會捨棄它保存在記憶體中的任務，並從 Redis 和資料庫重新讀取。對話方塊開啟時只勾選了
**Queue**；請只勾選卡住的群組。結果會顯示移除了多少筆記錄。

## Queue {#clusterClearDialog-queue}

等候某個節點啟動的任務。被清除的任務不會啟動：它們會以「等候中」狀態留在資料庫中。請停止它們，或再次執行它們的範本。

## Running {#clusterClearDialog-running}

叢集視為執行中的任務。清除並不會停止它們：任務會繼續在其執行器上執行。但叢集會失去對它的追蹤：該任務不再計入伺服器及其執行器的平行任務上限，
因此啟動的任務可能超過上限所允許的數量，而尚未被執行器接手的任務也不會再交給它。

## Active by project {#clusterClearDialog-active}

每個專案尚未結束的任務。它們用來執行專案的平行任務上限；當範本不允許平行任務時，也用來防止該範本在有任務執行時啟動第二個任務。
當某個專案的任務一直在已結束的任務後面等候時，請清除此群組。當下正在執行的任務將不再被計入，因此該專案的新任務可能會在它們旁邊同時啟動。

## Aliases {#clusterClearDialog-aliases}

Terraform、OpenTofu 和 Terragrunt 任務在其生命週期內取得的隨機名稱，對應到該任務。執行中的任務透過此名稱存取伺服器上的
Terraform 狀態：清除之後，就無法再透過此名稱找到這些應用程式的執行中任務。

## Claims {#clusterClearDialog-claims}

每個任務歸哪個節點所有。節點每分鐘會更新其任務的認領；未更新的認領會在五分鐘後過期。沒有認領的任務會被視為孤立任務：
尚未送達執行器的任務會被放回佇列，交給另一個節點；執行器已在執行的任務則會留在該處執行完畢。

## Runtime fields {#clusterClearDialog-runtimeFields}

資料庫中沒有保存的每個任務的詳細資訊：啟動它的使用者、啟動時所用的版本、它的別名、執行器和狀態，以及每個任務所屬的專案。
少了這些資訊，未啟動該任務的節點能顯示的相關內容會變少，而孤立任務的清理程序也會略過執行中的任務，因此卡住的記錄不會再自行被移除。
