# Edit Role

역할은 프로젝트 내부의 권한을 이름으로 묶은 것입니다. 역할은 프로젝트 멤버에게 부여하며, 멤버는 자신의 역할
중 어느 하나라도 허용하는 일을 할 수 있습니다. 프로젝트의 Roles 페이지에서 열면 이 대화 상자는 그 프로젝트의
역할만 수정하고, 프로젝트 밖의 Roles 페이지에서 열면 모든 프로젝트가 사용할 수 있는 공유 역할을 수정합니다.
기본 제공 역할인 Owner, Manager, Task Runner, Guest는 변경할 수 없습니다.

## 이름 {#role-name}

Roles 페이지와 역할을 선택하는 모든 곳(예: 프로젝트에 멤버를 추가할 때)에 표시되는 역할 이름입니다. 이
필드는 필수입니다. 역할 이름은 언제든지 바꿀 수 있습니다.

## Slug {#role-slug}

역할의 식별자입니다. 이름을 입력하는 동안 Semaphore가 이름에서 자동으로 채우며, 직접 슬러그를 수정하면
자동 채우기가 멈춥니다. 문자, 숫자, 밑줄, 하이픈으로 1~100자를 사용할 수 있습니다. 예: `release-managers`.

역할을 저장한 후에는 슬러그를 바꿀 수 없으며, 역할을 수정할 때 이 필드는 잠겨 있습니다.

- 슬러그는 고유해야 하며, 확인할 때 대소문자는 구분하지 않습니다. 공유 역할의 슬러그는 다른 모든 역할과
  달라야 하고, 프로젝트 역할의 슬러그는 공유 역할 및 같은 프로젝트의 다른 역할과 달라야 합니다.
- `owner`, `manager`, `task_runner`, `guest`, `all`은 대소문자와 관계없이 예약되어 있습니다.

## Permissions {#role-permissionsTitle}

이 역할을 가진 멤버가 프로젝트에서 할 수 있는 일입니다. 새 역할에는 체크된 권한이 없습니다. 멤버가 가진 모든
역할의 권한은 합산됩니다. Semaphore 관리자는 역할과 관계없이 모든 프로젝트에서 모든 일을 할 수 있습니다.

- **Can read project**: 프로젝트를 봅니다. 작업 템플릿, 작업과 그 로그, 인벤토리, 키, 리포지토리, 변수 그룹,
  일정, 멤버가 해당합니다. 프로젝트의 모든 읽기에 이 권한이 필요하며 다른 어떤 권한도 이를 포함하지 않으므로,
  거의 모든 역할에 체크하세요. 이 권한이 없으면 멤버는 해당 역할에 직접 액세스 권한을 부여한 작업 템플릿과
  워크플로, 그리고 그 작업만 봅니다.
- **Can run project tasks**: 작업 템플릿에서 작업을 시작하고 중지하며, 확인을 기다리는 작업을 확인하거나
  거부합니다.
- **Can update project**: 프로젝트 설정을 변경하고 프로젝트를 삭제합니다.
- **Can manage project resources**: 작업 템플릿, 인벤토리, 키, 리포지토리, 변수 그룹, 일정, 보기, 통합, 비밀
  저장소, 프로젝트 러너, 프로젝트의 역할을 만들고 변경하고 삭제합니다. 작업을 삭제하고, 어떤 역할이 작업
  템플릿을 사용할 수 있는지 설정합니다.
- **Can manage project users**: 프로젝트에 멤버를 추가하고, 멤버의 역할을 변경하고, 멤버를 제거합니다.
- **Can run workflows**: 워크플로를 시작하고 그 실행을 중지합니다.
- **Can edit workflows**: 워크플로를 만들고 변경하고 삭제하며, 어떤 역할이 워크플로를 사용할 수 있는지
  설정합니다.
- **Can approve workflows**: 승인을 기다리는 워크플로 실행 단계를 승인하거나 거부합니다.
