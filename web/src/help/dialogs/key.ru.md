# Редактировать Key

Ключ из раздела «Хранилище ключей» хранит учетные данные, которые проект использует, не показывая
их: SSH-ключ или пароль, с которым Ansible входит на хосты, учетные данные Git-репозитория, пароль
Ansible vault, секрет интеграции. Инвентари, репозитории, шаблоны задач и интеграции ссылаются на
ключ по его имени. После сохранения секрет никогда не отправляется обратно в браузер.

## Имя ключа {#key-name}

Имя, под которым ключ показан в разделе «Хранилище ключей» и в списках выбора ключа в инвентарях,
репозиториях, шаблонах задач и интеграциях. Поле обязательное. Выберите имя, которое говорит, что
открывает ключ, например `Deploy key of the web servers`.

## Источник {#key-source}

Где хранится секрет ключа. Вкладки:

- **Local**: секрет вводится в этом диалоге и хранится в базе данных Semaphore — в
  зашифрованном виде, если администратор задал ключ шифрования для ключей доступа. Это вариант по
  умолчанию.
- **Storage**: секрет хранится во внешнем хранилище секретов проекта, выбранном ниже в поле
  **Storage**. Эта вкладка есть только в версии Pro. Сами хранилища настраиваются на вкладке
  **Storages** раздела «Хранилище ключей».
- **Env**: секрет читается из переменной окружения процесса сервера Semaphore. Введите имя
  переменной в поле под вкладками.
- **File**: секрет читается из файла на сервере Semaphore. Введите абсолютный путь к файлу в поле
  под вкладками. Файл должен находиться внутри каталога секретов сервера (`dirs.secrets` в его
  конфигурации, по умолчанию `/tmp/semaphore`); путь за его пределами или путь с `..` приводит к
  ошибке при использовании ключа. Завершающий перевод строки в файле отбрасывается.

С **Env** и **File** Semaphore никогда не записывает секрет: он читает значение каждый раз, когда
задача использует ключ, поэтому секрет меняется там, где он хранится. Значение должно
соответствовать полю **Тип** ключа. Ключ **Строка** берет значение как есть. Ключ **SSH ключ** или
**Логин с паролем** ожидает JSON с полями этого типа, например:

```json
{"login": "deploy", "password": "s3cret"}
```

```json
{"login": "deploy", "passphrase": "", "private_key": "-----BEGIN OPENSSH PRIVATE KEY-----\n..."}
```

При редактировании ключа вкладки заблокированы, пока не установлен флажок **Переопределить**.
Ключ, синхронизированный из хранилища секретов, сохраняет свой источник, а его имя и тип нельзя
изменить.

## Storage {#key-sourceStorageId}

Показывается, когда выбрана вкладка **Storage**.

Хранилище секретов проекта, в котором находится секрет: HashiCorp Vault, OpenBao, Devolutions
Server, AWS Secrets Manager или Azure Key Vault, как настроено на вкладке **Storages** раздела
«Хранилище ключей».

- Хранилище, которое не только для чтения, получает секрет, введенный в этом диалоге: Semaphore
  записывает его туда при сохранении. При удалении ключа секрет удаляется и из хранилища. Ключ,
  хранящийся в таком хранилище, нельзя позже перенести в другое хранилище.
- Хранилище только для чтения только читается. Тогда диалог не показывает полей для секрета, и
  Semaphore читает его из хранилища каждый раз, когда задача использует ключ.

## Source Key {#key-sourceStorageKey}

Показывается, когда выбрано хранилище в поле **Storage**.

Где находится секрет в этом хранилище, например путь к секрету в HashiCorp Vault.

## Тип {#key-type}

Какие учетные данные хранит ключ. Поле обязательное, и поля под ним меняются вместе с типом.

- **SSH ключ**: закрытый ключ с необязательными логином и парольной фразой. С ним Ansible
  подключается к хостам, а Git клонирует репозиторий с URL `ssh`.
- **Логин с паролем**: логин и пароль. С ними Ansible подключается к хостам или становится другим
  пользователем (**Учетные данные sudo** инвентаря); Git клонирует с ними репозиторий `https`;
  пароль открывает Ansible vault шаблона задачи.
- **Строка**: одно секретное значение без логина: токен, API-ключ, пароль. Используйте его для
  секрета интеграции. Он не может быть SSH-ключом, учетными данными sudo, паролем vault или ключом
  доступа репозитория.
- **Нет**: без учетных данных. Используйте этот тип для репозитория, которому не нужен вход
  (публичный репозиторий `https`, URL `file` или локальный путь), и для инвентаря, хостам которого
  не нужны учетные данные или которые сами задают способ подключения.

## Имя пользователя {#key-loginPasswordLogin}

Показывается, когда выбран тип **Логин с паролем**. Необязательное поле.

Имя пользователя учетных данных.

- Ansible подключается к хостам от имени этого пользователя (`--user`); в качестве **Учетные
  данные sudo** инвентаря это пользователь, которым становится Ansible (`--become-user`). Если
  поле пустое, Ansible использует пользователя, указанного в инвентаре или в его собственной
  конфигурации.
- Для репозитория `https` Git входит с этим пользователем и паролем. Оставьте поле пустым для
  токена, который Git-сервер принимает сам по себе: тогда пароль отправляется как имя пользователя.

## Пароль {#key-loginPasswordPassword}

Показывается, когда выбран тип **Логин с паролем**. Обязательное поле.

Пароль учетных данных. Semaphore отвечает им на запросы пароля Ansible: пароль SSH
(`--ask-pass`) для учетных данных пользователя, пароль `become` (`--ask-become-pass`) для
учетных данных sudo и пароль vault для Ansible vault. Для репозитория `https` это пароль или
токен доступа Git-сервера.

## Значение {#key-stringValue}

Показывается, когда выбран тип **Строка**. Обязательное поле.

Само секретное значение, например токен, с которым интеграция сверяет получаемые запросы. Оно
хранится в том виде, в каком введено.

## Имя пользователя {#key-sshLogin}

Показывается, когда выбран тип **SSH ключ**. Необязательное поле.

Пользователь, от имени которого Ansible подключается к хостам (`--user`). Если поле пустое,
Ansible использует пользователя, указанного в инвентаре или в его собственной конфигурации.

Для Git-репозитория вместо этого укажите пользователя в URL репозитория, как в
`git@github.com:org/repo.git`.

## Passphrase {#key-sshPassphrase}

Показывается, когда выбран тип **SSH ключ**. Необязательное поле.

Парольная фраза, которой зашифрован закрытый ключ. Оставьте поле пустым для ключа без парольной
фразы. Неверная парольная фраза приводит к ошибке каждой задачи, использующей ключ, при загрузке
ключа. У ключа, созданного Semaphore, нет парольной фразы: содержимое этого поля тогда
отбрасывается.

## Generate SSH Key {#key-generateSshKey}

Показывается, когда выбран тип **SSH ключ**.

Semaphore создает новую пару ключей при сохранении: закрытый ключ RSA длиной 2048 бит, который
остается в ключе, и его открытый ключ, который показывается один раз в диалоге после сохранения, а
затем в поле **Public key** при каждом редактировании ключа. Добавьте открытый ключ в
`~/.ssh/authorized_keys` на хостах или как deploy key Git-репозитория.

Пока флажок установлен, поле закрытого ключа заблокировано. Для существующего ключа сначала
установите флажок **Переопределить**: старая пара ключей заменяется. Ключ, секрет которого
читается из **Env**, **File** или из хранилища только для чтения, нельзя сгенерировать, так как
Semaphore некуда его записать.

## Закрытый ключ {#key-sshPrivateKey}

Показывается, когда выбран тип **SSH ключ**. Обязательное поле, если не установлен флажок
**Generate SSH Key**.

Закрытый ключ в формате OpenSSH или PEM, включая строки `BEGIN` и `END`. Для задачи Semaphore
загружает его в собственный SSH-агент, которым Ansible и Git пользуются на время выполнения
задачи.

## Public key {#key-publicKey}

Показывается, когда вы редактируете SSH-ключ, сгенерированный Semaphore, пока флажок
**Переопределить** не установлен.

Открытая половина сгенерированной пары ключей. **Show** разворачивает ее, кнопка копирования
помещает ее в буфер обмена. Добавьте ее в `~/.ssh/authorized_keys` на хостах или как deploy key
Git-репозитория.

Это открытый ключ пары, которую Semaphore сгенерировал последней. Если вы вручную замените
закрытый ключ с помощью **Переопределить**, показанный здесь ключ ему больше не соответствует.

## Переопределить {#key-overrideSecret}

Показывается, когда вы редактируете существующий ключ.

Semaphore никогда больше не показывает сохраненный секрет, поэтому поля секрета пустые и
заблокированы. Установите флажок, чтобы заменить секрет: источник, тип и поля секрета
открываются, и все, что в них есть, сохраняется заново, поэтому введите весь секрет снова, а не
только изменившуюся часть. Без флажка при сохранении меняется только имя ключа.

При сохранении ключа также удаляются копии репозиториев, которые его используют, хранящиеся на
сервере Semaphore: следующая задача клонирует их заново.
