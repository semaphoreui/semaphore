# Редагувати шаблон 'Ansible Playbook'

Шаблон завдання визначає, що і як запускає Semaphore: репозиторій і файл у ньому, інвентар і
змінні, а також які опції користувач може змінити під час запуску завдання. Кожне завдання
запускається із шаблону. Поля діалогу залежать від застосунку шаблону (Ansible, Terraform,
OpenTofu, Terragrunt, Bash, Python, PowerShell та інші): поле, яке є лише в деяких застосунках,
про це повідомляє. Зміни діють для завдань, запущених після **Зберегти**.

## Тип шаблону {#templateForm-typeTabs}

Вкладки вгорі визначають вид шаблону:

- **Завдання**: виконує код. Більшість шаблонів саме такого виду.
- **Збірка**: створює артефакт. Кожне завдання збірки отримує версію, яка відраховується від
  **Початкова версія**.
- **Розгортання**: розгортає артефакт, створений збіркою. Під час запуску ви вибираєте завдання
  збірки, версію якого воно розгортає.

Завдання збірки або розгортання отримує у своєму середовищі змінні `SEMAPHORE_TASK_TYPE`,
`SEMAPHORE_TASK_TARGET_VERSION` (збірка) і `SEMAPHORE_TASK_INCOMING_VERSION` (розгортання).
Ansible отримує ті самі значення в додатковій змінній `semaphore_vars.task_details`.

## Початкова версія {#templateForm-startVersion}

Відображається, коли тип — **Збірка**. Обов’язкове поле.

Версія першого завдання збірки, наприклад `1.0.0` або `v0.1`. Кожна наступна збірка збільшує на
одиницю останнє число попередньої версії і зберігає текст навколо нього та його доповнення
нулями: `1.0.0`, `1.0.1`, `1.0.2`. Збільште тут число вище за останню збірку, щоб перескочити
вперед, наприклад до `2.0.0`; версія без числа ніколи не змінюється.

## Шаблон збірки {#templateForm-buildTemplateId}

Відображається, коли тип — **Розгортання**. Обов’язкове поле.

Шаблон, завдання якого створюють артефакти, що їх розгортає цей шаблон. Список містить шаблони
збірки проєкту, а під ними — шаблони розгортання: розгортання може йти за іншим розгортанням і
тоді отримує версію, яку те розгортання отримало від своєї збірки.

## Автозапуск {#templateForm-autorun}

Відображається, коли тип — **Розгортання**.

Автоматично запускає завдання цього шаблону щоразу, коли завдання з **Шаблон збірки** завершується
успішно, з версією, яку створило те завдання. Невдала збірка нічого не запускає.

## Ім’я {#templateForm-name}

Назва, під якою шаблон відображається на сторінці «Шаблони завдань». Поле обов’язкове.

## Репозиторій {#templateForm-repositoryId}

Репозиторій проєкту, який містить код для виконання. Поле обов’язкове. Перед кожним завданням
Semaphore оновлює свою копію репозиторію і виконує код звідти.

Мітка праворуч від поля показує гілку, яку отримують завдання. Натисніть її, щоб відкрити поле
**Гілка**.

## Гілка {#templateForm-gitBranch}

Відображається після кліку на мітці гілки праворуч від **Репозиторій**.

Гілка або тег, які отримують завдання цього шаблону замість гілки, заданої в репозиторії.
Залиште поле порожнім, щоб використовувати гілку репозиторію. Коли Semaphore може прочитати гілки
репозиторію, поле їх пропонує.

Поле неактивне, коли репозиторій є монорепозиторієм: усі шаблони спільно використовують одну його
копію на гілці репозиторію.

## Шлях до файлу playbook {#templateForm-playbook}

Що виконувати, як шлях від кореня репозиторію, наприклад `deploy/site.yml`. Шлях не може бути
абсолютним і не може виходити за межі репозиторію. Список пропонує файли репозиторію; можна також
ввести шлях, якого немає у списку. Кнопка праворуч від поля знову зчитує список.

Підпис і значення змінюються залежно від застосунку:

- **Ansible**: playbook. Поле обов’язкове; список пропонує файли `.yml` і `.yaml`.
- **Terraform**, **OpenTofu**, **Terragrunt**: **Subdirectory path**, каталог із кодом. Залиште
  поле порожнім, щоб виконувати код у корені репозиторію. Введіть `/`, щоб побачити вміст
  каталогу.
- **Bash**, **Python**, **PowerShell** та інші застосунки: **Script Filename**, скрипт для
  виконання. Поле обов’язкове. Скрипт виконується в корені репозиторію.

## Different working directory {#templateForm-workingDirectoryToggle}

Відображається для шаблонів Ansible.

Запускає `ansible-playbook` в іншому каталозі, ніж корінь репозиторію. Встановіть прапорець, щоб
показати поле **Working directory**. Зніміть його, щоб знову виконувати в корені.

## Working directory {#templateForm-workingDirectory}

Відображається, коли встановлено **Different working directory**. Обов’язкове поле.

Каталог, у якому запускаються `ansible-playbook` і `ansible-galaxy`, як шлях від кореня
репозиторію, наприклад `ansible`. Використовуйте його, коли `ansible.cfg` проєкту лежить у
підкаталозі, бо Ansible читає цей файл із поточного каталогу. Шлях до playbook і далі
відраховується від кореня репозиторію. Шлях не може бути абсолютним і не може виходити за межі
репозиторію.

## Інвентар {#templateForm-inventoryId}

Відображається для шаблонів Ansible, Terraform, OpenTofu і Terragrunt.

- **Ansible**: інвентар, з яким виконується playbook, з обліковими даними для хостів. Поле
  обов’язкове.
- **Terraform**, **OpenTofu**, **Terragrunt**: **Workspace**, workspace, у якому виконується
  код. Semaphore вибирає його перед планом і створює, якщо його немає. Новий шаблон, збережений
  без workspace, отримує workspace з назвою `default`.

Список містить інвентарі проєкту, створені для застосунку шаблону.

## середовище {#templateForm-environmentIds}

Необов’язкове поле. Групи змінних, змінні, змінні середовища і секрети яких отримує кожне
завдання цього шаблону. Можна вибрати кілька: вони об’єднуються в порядку поля, і пізніша група
перемагає попередню, коли обидві задають ту саму назву.

Як змінні потрапляють у код, залежить від застосунку: додаткові змінні для Ansible, `-var` для
Terraform і OpenTofu, аргументи `name=value` для скрипта. Змінні середовища задаються для всіх
застосунків.

## Перегляд {#templateForm-viewId}

Необов’язкове поле. Перегляд, у якому відображається шаблон: перегляди — це вкладки сторінки
«Шаблони завдань», які групують шаблони проєкту. Залиште поле порожнім, щоб не додавати шаблон до
жодного перегляду.

## Тег виконавця {#templateForm-runnerTag}

Відображається, коли доступні виконавці проєкту.

Завдання цього шаблону виконуються лише на виконавці, який має цей тег, навіть коли сервер міг би
виконати їх сам. Тег перевизначає тег виконавця інвентарю. Залиште поле порожнім, щоб
використовувати тег інвентарю або жодного.

## Executor image {#templateForm-executorImage}

Образ контейнера, який виконавець запускає для завдань цього шаблону, наприклад
`semaphoreui/job:latest`. Залиште поле порожнім, щоб використовувати образ із конфігурації
виконавця.

Лише виконавці Docker і Kubernetes запускають завдання в контейнері, тож поле активне, лише коли
доступний один із них. Завдання, яке виконується без контейнера, його ігнорує.

## Змінні опитування {#surveyVars}

Значення, які користувача просять ввести під час запуску завдання цього шаблону. Натисніть **+**,
щоб додати змінну, чип — щоб змінити її, хрестик на чипі — щоб її видалити; перетягуйте чипи, щоб
задати порядок запитань.

Відповіді потрапляють у код як змінні групи змінних або як змінні середовища, залежно від
налаштування кожної змінної. Вони перемагають групу змінних, яка задає ту саму назву.

## Дозволити паралельні завдання {#templateForm-allowParallelTasks}

Дозволяє завданням цього шаблону виконуватися одночасно. Без цього завдання шаблону чекає в
черзі, доки не завершиться поточне. Ліміти паралельних завдань проєкту і сервера діють у
будь-якому разі.

## Issue JWT to task runner {#templateForm-jwtEnabled}

Відображається, коли адміністратор увімкнув для сервера видачу JWT.

Дає кожному завданню цього шаблону JSON Web Token, підписаний Semaphore, у змінній середовища
`SEMAPHORE_JWT`. Код може показати токен іншому сервісу, щоб довести, яке це завдання: токен
називає завдання, проєкт, шаблон і користувача, який його запустив. Сервіс перевіряє підпис за
публічними ключами за адресою `/.well-known/jwks.json` сервера Semaphore.

## JWT audience {#templateForm-jwtAudience}

Відображається, коли встановлено **Issue JWT to task runner**. Необов’язкове поле.

Сервіси, для яких призначено токен, записані в його claim `aud`, наприклад
`https://vault.example.com`. Натискайте Enter після кожного значення. До 32 значень; залиште поле
порожнім для токена без audience.

## JWT TTL {#templateForm-jwtTtl}

Відображається, коли встановлено **Issue JWT to task runner**. Необов’язкове поле.

Як довго токен залишається дійсним від початку завдання, у вигляді тривалості, наприклад `30s`,
`15m` або `1h`. Залиште поле порожнім, щоб використати значення сервера за замовчуванням — одну
годину, якщо адміністратор не задав іншого. Значення не може перевищувати максимум сервера —
24 години, якщо не задано інакше.

## Я хочу запускати завдання по розкладу лише для нових комітів певного репозиторія {#templateForm-cronVisible}

Запускає завдання цього шаблону, коли в репозиторії з’являється новий коміт. Semaphore з вибраним
інтервалом запитує в репозиторію його останній коміт і запускає завдання, лише якщо коміт
змінився після останньої перевірки.

Встановлення прапорця і збереження створює розклад перевірки; зняття прапорця і збереження
видаляє цей розклад. Інші розклади шаблону зберігаються.

## Репозиторій {#templateForm-cronRepositoryId}

Відображається, коли встановлено
**Я хочу запускати завдання по розкладу лише для нових комітів певного репозиторія**.
Обов’язкове поле.

Репозиторій, за новими комітами якого слід стежити. Semaphore стежить за гілкою, заданою в цьому
репозиторії, а не за **Гілка** шаблону.

## інтервал перевірки {#templateForm-cronFormat}

Відображається, коли встановлено
**Я хочу запускати завдання по розкладу лише для нових комітів певного репозиторія**.

Як часто Semaphore перевіряє репозиторій на новий коміт: від щохвилини до одного разу на день. За
замовчуванням — щохвилини.

## Не показувати сповіщення про успіх {#templateForm-suppressSuccessAlerts}

Не дає завданням цього шаблону, які завершуються успішно, надсилати сповіщення. Сповіщення про
невдалі завдання і далі надсилаються. Діє, лише коли для проєкту ввімкнено сповіщення.

## Не показувати сповіщення про помилки {#templateForm-suppressErrorAlerts}

Не дає завданням цього шаблону, які завершуються з помилкою, надсилати сповіщення. Сповіщення про
успішні завдання і далі надсилаються. Діє, лише коли для проєкту ввімкнено сповіщення.

## CLI args {#templateForm-args}

Аргументи, які додаються до команди кожного завдання. Кожен чип — один аргумент, що передається як
є, без оболонки: вкажіть `--forks=10` в одному чипі або `--forks` і `10` у двох. Перетягуйте чипи,
щоб змінити їхній порядок. Кнопка праворуч від списку відкриває аргументи як масив JSON:

```json
["--forks=10", "-e", "env=staging"]
```

- **Ansible**: додаються до `ansible-playbook` перед playbook.
- **Terraform**, **OpenTofu**, **Terragrunt**: додаються до `plan` і `apply`, але не до `init`.
- Скрипт: додаються після назви скрипта.

## CLI-аргументи {#templateForm-allowOverrideArgsInTask}

У розділі **Підказки**. Дозволяє користувачеві додати власні аргументи під час запуску завдання.
Вони додаються після аргументів шаблону.

## Гілка {#templateForm-allowOverrideBranchInTask}

У розділі **Підказки**. Дозволяє користувачеві вибрати іншу гілку, тег або коміт під час запуску
завдання замість гілки шаблону. Без цього завдання завжди отримує гілку шаблону.

Прапорець неактивний, коли репозиторій є монорепозиторієм.

## Інвентар {#templateForm-allowOverrideInventory}

У розділі **Підказки**. Відображається для шаблонів Ansible, Terraform, OpenTofu і Terragrunt.

Дозволяє користувачеві вибрати інший інвентар під час запуску завдання. Вибраний там інвентар
використовують лише шаблони Ansible: завдання Terraform, OpenTofu або Terragrunt виконується у
workspace шаблону, навіть коли прапорець установлено.

## Обмеження {#templateForm-limit}

Відображається для шаблонів Ansible.

Хости або групи з інвентарю, на яких слід виконати playbook, що передаються як `--limit`. Кожен
чип — один шаблон, наприклад `web` або `db01`; залиште список порожнім, щоб виконати на всіх
хостах.

## Теги {#templateForm-tags}

Відображається для шаблонів Ansible.

Виконує лише завдання і ролі з цими тегами, що передаються як `--tags`. Залиште список порожнім,
щоб виконати все.

## Пропустити теги {#templateForm-skipTags}

Відображається для шаблонів Ansible.

Пропускає завдання і ролі з цими тегами, що передаються як `--skip-tags`.

## Сховища {#templateVaults}

Відображається для шаблонів Ansible.

Паролі Ansible Vault, потрібні playbook для розшифрування його файлів. Натисніть **+**, щоб додати
пароль, чип — щоб змінити його, хрестик на чипі — щоб його видалити. Кожне сховище має назву, свій
vault ID і бере пароль із ключа «Сховища ключів» або з клієнтського скрипта репозиторію.

## Автоматичне підтвердження {#templateForm-autoApprove}

Відображається для шаблонів Terraform, OpenTofu і Terragrunt.

Застосовує план без запитання. Без цього завдання зупиняється після плану і чекає, доки
користувач не підтвердить або не відхилить його; план без змін завершує завдання, не маючи чого
застосовувати.

## Перезапис параметрів бекенду {#templateForm-overrideBackend}

Відображається для шаблонів Terraform, OpenTofu і Terragrunt, коли Semaphore може зберігати стан
Terraform.

Зберігає стан коду в Semaphore. Перед `init` Semaphore записує в каталог коду файл, який задає
бекенд `http`, і видаляє його після завдання:

```hcl
terraform {
  backend "http" {
  }
}
```

## Ім'я файлу бекенду {#templateForm-backendFilename}

Відображається разом із **Перезапис параметрів бекенду**; активне, коли цей прапорець
установлено. Необов’язкове поле.

Назва файлу, в який Semaphore записує бекенд, наприклад `semaphore_backend.tf`. За
замовчуванням `backend.tf`. Назва має закінчуватися на `.tf` і містити лише літери, цифри, `_`,
`-` і `.`. Оберіть назву, якої немає в жодного файлу вашого коду: Semaphore перезаписує цей файл
і видаляє його після завдання.

## Обмеження {#templateForm-allowOverrideLimit}

У розділі **Підказки для Ansible**. Дозволяє користувачеві задати хости для виконання під час
запуску завдання замість **Обмеження** шаблону.

## Теги {#templateForm-allowOverrideTags}

У розділі **Підказки для Ansible**. Дозволяє користувачеві задати теги під час запуску завдання
замість **Теги** шаблону.

## Пропустити теги {#templateForm-allowOverrideSkipTags}

У розділі **Підказки для Ansible**. Дозволяє користувачеві задати теги, які слід пропустити, під
час запуску завдання замість **Пропустити теги** шаблону.

## Налагодження {#templateForm-allowDebug}

У розділі **Підказки для Ansible**. Дозволяє користувачеві ввімкнути докладний вивід під час
запуску завдання, від `-v` до `-vvvvvv`.

## Тестовий запуск {#templateForm-showDryRun}

У розділі **Підказки для Ansible**. Установлено за замовчуванням. Пропонує опцію
**Тестовий запуск** під час запуску завдання, яка запускає playbook з `--check`: Ansible
повідомляє, що він змінив би, і нічого не змінює. Зніміть прапорець, щоб прибрати цю опцію.

## Порівняння {#templateForm-showDiff}

У розділі **Підказки для Ansible**. Установлено за замовчуванням. Пропонує опцію **Порівняння**
під час запуску завдання, яка запускає playbook з `--diff`, щоб показати зміни, внесені у файли.
Зніміть прапорець, щоб прибрати цю опцію.

## Автоматичне підтвердження {#templateForm-allowAutoApprove}

У розділі підказок для Terraform, OpenTofu і Terragrunt. Дозволяє користувачеві встановити
**Auto Approve** під час запуску завдання, щоб застосувати план без підтвердження. Діалог завдання
пропонує цю опцію в будь-якому разі, але без цього прапорця Semaphore її ігнорує: завдання чекає
на підтвердження після плану, якщо не встановлено **Автоматичне підтвердження** шаблону.

## Galaxy install options {#templateForm-galaxy}

Відображається для шаблонів Ansible. Натисніть, щоб показати опції встановлення Galaxy; підпис
показує кількість опцій, які відрізняються від стандартних.

Перед запуском playbook Semaphore за допомогою `ansible-galaxy` встановлює ролі та колекції, яких
вимагає репозиторій. Він шукає `requirements.yml`, `roles/requirements.yml` і
`collections/requirements.yml` поруч із playbook і в корені репозиторію і виконує встановлення,
лише якщо файл змінився після останнього завдання.

## Skip Galaxy install {#templateForm-skipGalaxyInstall}

У розділі **Galaxy install options**. Пропускає встановлення Galaxy: playbook виконується з
ролями та колекціями, встановленими раніше. Використовуйте це, коли залежності встановлюються
іншим способом або встановлення повільне і непотрібне.

## Role install args {#templateForm-galaxyRoleArgs}

У розділі **Galaxy install options**. Аргументи, які додаються до `ansible-galaxy role install`,
по одному на чип, наприклад `--ignore-certs` або `--server=https://galaxy.example.com`. Semaphore
приймає лише ті прапорці встановлення, які безпечно передавати: невідомий прапорець, `--token`,
`--api-key`, `-p` або `--roles-path` не дає зберегти шаблон.

## Collection install args {#templateForm-galaxyCollectionArgs}

У розділі **Galaxy install options**. Аргументи, які додаються до
`ansible-galaxy collection install`, по одному на чип, наприклад `--pre` або `--upgrade`. Діє те
саме правило, що й для **Role install args**: `--token`, `--api-key`, `-p` і `--collections-path`
не приймаються.

## Skip Galaxy install {#templateForm-allowOverrideSkipGalaxyInstall}

У розділі **Galaxy install options**, у **Prompts**. Дозволяє користувачеві під час запуску
завдання вибрати, чи пропускати встановлення Galaxy. Вибір завдання перемагає
**Skip Galaxy install** шаблону.
