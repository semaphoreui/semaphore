# Workflow permissions

Надає ролі додаткові права на цей окремий workflow. Учасник із цією роллю отримує їх на додачу до
прав, які роль має в усьому проєкті: надання тут лише додає, воно ніколи не забирає права.
Учасник із кількома ролями отримує кожне право, надане будь-якій із них.

## Роль {#templatePerm-roleSlug}

Роль, яка отримує права. Список показує ролі цього проєкту, спільні ролі та вбудовані ролі. Поле
обов’язкове, і роль може мати лише одне надання на workflow: сервер відхиляє друге.

Роль збереженого надання змінити не можна. Сервер зберігає роль і записує лише права, що б ви тут
не вибрали. Щоб надати права іншій ролі, видаліть це надання зі списку і додайте нове.

## Права {#templatePerm-permissionsTitle}

Що учасник із цією роллю може робити з цим workflow:

- **Can see this workflow**: workflow є у списку workflow разом із його виконаннями.
- **Can run this workflow**: запускати виконання workflow.
- **Can edit this workflow**: змінювати й видаляти workflow і керувати цими правами.
- **Can approve this workflow**: схвалювати або відхиляти кроки схвалення його виконань.

Запуск, редагування або схвалення включає перегляд workflow: коли ви позначаєте будь-яке з них,
**Can see this workflow** теж позначається, і його не можна зняти. Залиште всі прапорці знятими,
щоб зберегти надання, яке нічого не дає.
