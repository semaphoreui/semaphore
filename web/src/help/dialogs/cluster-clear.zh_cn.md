# Clear tasks from Redis

集群的节点在 Redis 中共享任务池的状态：哪些任务在等待、哪些在运行，以及每个任务归哪个节点所有。此对话框从 Redis
中删除您勾选的记录组，用于恢复卡住的集群，例如某个已完成的任务仍显示为正在运行。不会从数据库中删除任何内容：
任务会保留其状态、日志和历史。

无论您勾选什么，每个节点都会丢弃其保存在内存中的任务，并从 Redis 和数据库中重新读取它们。对话框打开时只勾选了
**Queue**；请只勾选卡住的组。结果会显示删除了多少条记录。

## Queue {#clusterClearDialog-queue}

等待节点启动的任务。被清除的任务不会启动：它们以 Waiting 状态保留在数据库中。请停止它们，或者重新运行它们的模板。

## Running {#clusterClearDialog-running}

集群视为正在运行的任务。清除不会停止它们：任务会继续在其运行器上运行。但集群会失去对它的跟踪：该任务不再计入服务器及其运行器的并行任务上限，
因此启动的任务可能多于上限所允许的数量，并且尚未被运行器领取的任务不会再交给该运行器。

## Active by project {#clusterClearDialog-active}

每个项目中未完成的任务。它们用于执行项目的并行任务上限，并在模板不允许并行任务时，阻止该模板在一个任务运行期间启动第二个任务。
当某个项目的任务一直排在已经结束的任务后面等待时，请清除此组。此时正在运行的任务将不再计入，因此项目的新任务可能会与它们同时启动。

## Aliases {#clusterClearDialog-aliases}

Terraform、OpenTofu 和 Terragrunt 任务在其生命周期内获得的随机名称，映射到对应的任务。正在运行的任务通过此名称访问服务器上的
Terraform 状态：清除之后，这些应用的正在运行的任务将无法再通过该名称被找到。

## Claims {#clusterClearDialog-claims}

每个任务归哪个节点所有。节点每分钟续订一次其任务的认领；未续订的认领会在五分钟后过期。没有认领的任务被视为孤立任务：
尚未交给运行器的任务会被放回队列，交给另一个节点；运行器已经在运行的任务则留在那里运行完毕。

## Runtime fields {#clusterClearDialog-runtimeFields}

数据库中不保存的每个任务的详细信息：启动它的用户、启动时使用的版本、其别名、运行器和状态，以及每个任务所属的项目。
没有这些信息，未启动该任务的节点显示的关于它的信息会更少，并且孤立任务的清理程序会跳过正在运行的任务，因此卡住的记录将不再被自动删除。
